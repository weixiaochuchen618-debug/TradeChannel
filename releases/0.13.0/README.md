# TradeChannel 0.13.0 预览版

完整解压到固定目录，双击 TradeChannel.exe。打开管理界面读取现有状态；连接、断开和更换线路由用户明确操作。

标准部署在同一次向导中准备 UDP 和 TCP：完成服务器服务、本机两套配置及云端入站规则清单，再自动对比连接方式。UDP/TCP 是同一条线路的两个属性，不生成两条线路。

两套配置齐全才显示“部署配置完整”。某种方式在当前网络无法连接，不等于它没有部署；TCP 组件安装或本机配置生成失败则显示“部署部分完成”。软件保留已有成果，可继续完成部署，或明确选择“先使用已准备方式”。

部署结束后：

- 有合格推荐：查看依据、样本和时间，点击“连接推荐方式”，核对预览后连接；也可以稍后使用。
- 明确指定 UDP/TCP：保留手动选择，检查结果单独显示。
- 两种失败、身份在用、路径无法核对或证据过期：说明原因，不把失败方式兜底为默认推荐，保留已准备的服务器和本机资料。

日常选择一条线路即可。UDP/TCP 是同一线路的连接方式。连接方式页中的默认值只影响下次连接；更改默认值不会切换现有通道。旧线路在首次点击连接时自动整理本机连接资料，不重新部署服务器或新增设备。

日常“改用 UDP/TCP”只使用已保存的配置，核对、重连并检查出口，不登录服务器、不安装组件。缺少另一套配置的旧线路在管理维护入口一次性完善；普通连接失败不会自动打开补充部署。

线路卡优先显示实际正在使用的方式和本次会话检查结果；失败、结论不足、身份阻断和历史过期分别显示。“连接检查”通过后直接继续使用。

探针采用独立用户态引擎和本地认证入口。正式配置与探针保存相同的外层网卡和 DNS 绑定；观察条件不满足时不冒称物理直连。在用 WireGuard 身份不能另开候选探针，避免影响现有连接。

对比采用串行、交替顺序的配对轮次，按同一目标分别统计成功、超时和响应时间。只有同网络、同请求预算、可信出口、实际路径观测与清理条件均满足时，质量数据才参与推荐；相近或样本不足时明确使用默认策略。手动选择优先，运行中不静默切换。

推荐与服务器/设备身份、连接方式、配置与引擎完整性、网络环境和时间绑定。网络或配置变化后重新核对；有限 HTTPS 样本不表示裸 RTT、真实丢包率、交易延迟或长期交易稳定性。

Linux 授权返回的 MTU 自动进入本机导出、TUN、WireGuard 和独立探针配置。旧服务器未返回 MTU 时保持旧行为，不自动覆写已有运行配置。新增电脑的加密授权也传递并校验 MTU。

实际启用使用受控事务：核对预览、停止原会话、启动目标、验证出口，失败按原状态恢复并复测。配置还原不等于连接或交易软件业务恢复。请先退出整个 NinjaTrader 再切换；行情、登录与订单需在交易软件中核对。

部署需要对应服务器权限与云端入口规则。购买、云账户操作和新线路启用由用户明确确认。新增电脑使用独立授权与加密交接，不复制另一台电脑的身份。
