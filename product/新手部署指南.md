# TradeChannel 向导预览版 · 新手部署指南

版本 0.8.0。提供原生 Windows 控制台、节点导入、设置迁移与服务器配置向导。界面分为「概览、线路、部署、设置」四页：概览负责连接与三条流量线（交易、日常上网、AI 助手），其余页面管理线路与 AI 助手名单、部署和维护。

新版服务商统一操作见 [服务商接入](服务商接入.md)。下文 BatVPN 操作仅适用于 BatVPN 客户端；Clash Verge 使用独立流程。已上线 0.6.0 可继续运行，新界面不会自动更新在线线路。


当前为向导预览版：普通操作仍在管理员会话内运行，正式 Windows 服务/普通用户 IPC、完整签名安装器、加密身份灾难恢复包尚未交付。服务器真实部署需要在目标 Windows Server 上验收，不能用本机 Windows 11 的测试代替。

## 先回答：还需要 WireGuard 吗？

| 位置 | 需要什么 | 日常怎么用 |
|---|---|---|
| 本地交易电脑 | sing-box 内置 WireGuard 协议实现；包内 `wg.exe` 仅用于配置/密钥工具 | 使用 TradeChannel，不打开旧 WireGuard 隧道 |
| 自建转发服务器 | WireGuard 服务、转发/NAT、防火墙 | 服务后台运行，交易电脑连接它 |
| 使用服务商时 | Clash Verge、BatVPN 或本机 SOCKS5 客户端 | 先登记、准备和检查，再选择出口；详见 [服务商接入](服务商接入.md) |

已有本地 WireGuard 暂时保留，便于导出和回退。不要把“协议不再需要”与“无需手动操作旧 GUI”混淆。旧 `client` 隧道和新通道不能同时使用同一客户端密钥上线。

## 0. 打开软件

1. 完整解压 ZIP 到固定目录，例如桌面的 `TradeChannel` 文件夹。不要在压缩包里直接运行，不要只复制单独 EXE。
2. 双击 `TradeChannel.exe`，在 Windows 的管理员权限提示中选择允许。
3. 首页只读取当前状态，不自动切换网络。没有配置时点击左侧「部署向导」。
4. 包含校验清单；文件缺失或校验失败时停止启动。预览版没有商业代码签名，不要把其 SHA256 清单等同官方数字签名。
5. 关闭窗口会收起到系统托盘。需要退出界面时右键托盘图标；界面退出不停止交易通道。
6. 没有桌面入口时，双击解压目录内「创建桌面入口.cmd」，或在控制台「设置 → 创建桌面快捷方式」。之后从桌面 TradeChannel 图标打开；不要只把 EXE 单独拖到桌面。

如果出现乱码，请使用包内启动器；脚本已经按 Windows PowerShell 5.1 所需的 UTF-8 BOM 保存，不用更改整机语言或执行策略。

## 1. 当前这台电脑已有可用通道

这是你现在最适合的路径：

1. 打开「线路」。
2. 点击「登记当前通道」。
3. 这只把现有节点登记到列表，**不重启、不重新生成密钥、不改变当前线路**。
4. 回到「连接」，核对「当前生效」的范围、出口和运行状态；页面定期核对实际会话。
5. 若只是查看和登记，NinjaTrader 可以保持运行。导入并启用另一节点时则需要退出整个 NinjaTrader。

## 2. 一台新的本地交易电脑

### 情况 A：已经有客户端 `.conf` 或 WireGuard 导出 `.zip`

1. 「部署向导」选择「配置交易电脑」。
2. 看环境检查：系统、权限、引擎、NinjaTrader 路径。没有 NinjaTrader 时可只使用网页交易。
3. 选择连接文件并给节点命名，例如「香港主线」。这里必须是客户端配置，不能把服务器配置导入为客户端。
4. 如果文件还在旧 WireGuard：打开本机 WireGuard 左下角下拉菜单 →「导出所有隧道到 zip」→ 保存到安全目录 → 返回向导选择文件。
5. 检查 NinjaTrader 程序路径和本地 DNS。只用 TradingView 可把程序路径留空。不要把整个 Chrome/WebView2 程序作为 NinjaTrader 路径。
6. 服务商可稍后在「线路」页登记；只配置自建线路也能完成部署。首次添加多个服务商见 [服务商接入](服务商接入.md)。
7. 「保存并校验线路」只写入候选配置，不切换网络。
8. 到「线路」点击「设为交易线路」（或在概览页「交易」中选择该线路）。退出 NinjaTrader 整个控制中心后点击「连接」；已连着旧节点时确认切换。后台备份旧设置、启用并检查出口；失败时尝试停止候选、恢复旧部署记录，之后手动连接。停止未完成时保留故障身份并提示处理。
9. 显示出口通过后，再启动 NinjaTrader。登录、实时行情、历史 K 线和 TradingView 分别检查。考核账户不要为了验收强行成交。

### 情况 B：没有客户端配置，需要服务器授权这台新电脑

1. 在「部署向导」点击「申请或完成设备授权」。
2. 点击「生成设备申请」，选择一个新的空目录。其中私钥留在本机，只把公开申请文件复制给服务器。
3. 服务器管理员在其 TradeChannel 的同一页面进入「服务器授权入口」，分配没有占用的 VPN 地址。
4. 把服务器返回的授权文件复制回本机。
5. 选择原申请目录和返回文件，合成客户端 `.conf`；之后按情况 A 导入。
6. 新电脑使用独立身份。不要把旧电脑同一客户端私钥复制过去并同时运行。

## 3. 在新的香港／美国 Windows Server 配置

新服务器采用 Linux 时，使用独立的 [Linux 部署指南](Linux部署指南.md)：在本机选择「部署 → 部署 Linux 服务器」，通过 SSH 完成检查、计划、安装与设备授权。Linux 不执行下文的 Windows 安装程序，也不需要远程桌面。

1. 用远程桌面登录目标服务器。确认自己还能够通过服务器厂商控制台恢复访问。
2. 将完整安装包复制到服务器，运行 `TradeChannel.exe`，选择「转发服务器」。
3. 先看检查结果。已有 WireGuard/NAT 时优先保留；本版新建向导发现冲突会停止，不强制覆盖旧部署。
4. 没装 WireGuard 时，可选「使用随包安装程序」或「从官网下载并安装」。两者均先校验 WireGuard LLC 官方签名。随包的是约 85 KB 的联网引导器，运行时仍需下载完整组件；官网选项先下载同类引导器。已经安装时保留原组件，不启动旧隧道。服务器无法访问下载站时，两种引导器均不能完成下载，需先恢复官网访问。
5. 填写节点名称、公网 IPv4:UDP端口、实际外网网卡和未冲突网段。示例公网地址是文档保留地址，不能直接照抄上线。
6. 点击「生成变更计划」，先看清哪些服务、NAT、转发和防火墙规则会新增。
7. 打开服务器厂商的云控制台，找到这台 VPS 的安全组/入站规则，允许同一 UDP 端口。不要删除远程桌面的管理端口规则。
8. 回到向导「应用服务器计划」。它不接管服务器自己的默认路由；失败保留回滚记录。
9. 添加交易电脑的公开设备申请，给每台电脑分配不同地址，返回授权文件。
10. 在客户端实际验证握手和公网转发。本机规则成功不代表云安全组也正确；只有 ping 通也不等于能访问外网。

如果这台服务器本身要运行 NinjaTrader，它还是一台「交易电脑」。不建议在同一系统同时叠加两个角色；向导不自动配置服务器连回自己。

## 4. 从香港换到美国

1. 原香港节点保持不变。
2. 美国服务器按上面的服务器流程部署。
3. 为当前交易电脑建立该美国节点上的独立授权。
4. 本机「线路」点击「添加自建线路」导入美国客户端配置；保存后选择此线路，再到「连接」应用。
5. 更换线路会使软件重连，不能在不知账户状态时随意测试。
6. 新节点实际验证稳定前，保留香港节点和原始备份。

不只修改旧配置里的服务器 IP。美国服务器拥有自己的公钥、授权与地址；速度也要通过真实交易服务检查，不以地理位置判断。

## 5. 换电脑、加第二台电脑

1. 旧电脑「部署向导 → 换电脑 / 迁移设置」导出设置包。
2. 新电脑解压安装包并导入设置，节点显示待授权是正常状态。
3. 新电脑重新识别软件位置、DNS、网卡与服务商；旧电脑的 PID/网卡索引不会迁移。
4. 新电脑生成设备申请，由服务器授权，合成客户端配置再启用。
5. 如果是替换旧电脑，新机验收后再停用旧设备；如果两台都使用，应保留两个不同 Peer。

默认设置迁移包不包含任何私钥、代理密码或交易账户，不等于可直接联网的密钥备份。密码加密的完整身份恢复包不在当前预览版中；不要把设置包当作灾难恢复的唯一材料。

## 6. 每天怎么用

### 打开电脑以后

1. 双击 `TradeChannel.exe`。默认不会自动建立通道。
2. 「概览」页顶部是实际状态，下面「流量走向」有三条线：**交易**、**日常上网**和 **AI 助手**。
3. 需要日常上网走 BatVPN 时，先打开 BatVPN 连接节点，保持其**白名单**模式。
4. 点击主按钮「连接」，等到「已连接」。可以在「出口检查」查看交易出口和日常出口。
5. 打开 NinjaTrader 和 TradingView，分别核对账户、实时行情、历史图表。网络出口检查不等同订单系统验收。

### 三条线怎么选

| 线 | 选项 | 作用 |
|---|---|---|
| 交易 | 香港主线（或其他自建线路） | NinjaTrader、TradingView、Tradovate 经该自建服务器转发 |
| 交易 | BatVPN 备用 | 香港故障时手动使用；先在 BatVPN 切到**全局**模式 |
| 日常上网 | 本地直连 | 其他应用直接使用本地网络 |
| 日常上网 | BatVPN | 其他应用交给 BatVPN：国内网站按其白名单直连，外网经 BatVPN 节点 |
| 日常上网 | 走交易线路 | 所有应用都经交易线路（原「全部流量」）；会与交易共用服务器带宽 |
| AI 助手 | 跟随日常上网 | 名单内的助手与其他应用一样，按「日常上网」的选择出网 |
| AI 助手 | 走交易线路 | 只有名单内的助手经交易线路转发，其他应用照常 |

**日常上网和 AI 助手的选择点击即生效**，不影响交易连接。**切换交易线路会先确认**，因为 NinjaTrader、TradingView 的现有连接会中断，需要重新连接；换成另一台自建服务器还要先退出整个 NinjaTrader。未连接时，任何选择只保存为下次连接使用。

选 BatVPN 但 BatVPN 未连接、端口被其他程序占用或暂时无法转发时，日常上网自动保持直连，并在线路下方说明原因；BatVPN 恢复并通过转发检查后自动切回。交易线路不受影响。

香港故障时：BatVPN 切到全局 → 概览页「交易」选 BatVPN 备用并确认 → 在 NinjaTrader 中重新连接 → 核对账户。当前没有自动故障切换；BatVPN 历史行情稳定性仍需实际验证。香港恢复后切回自建线路，BatVPN 改回白名单。

### AI 助手名单

需要某些 AI 助手稳定走香港，而其他日常流量照常走 BatVPN 或本地网络时使用。

- **选助手**：在「线路」页「AI 助手名单」逐项打开或关闭。
  - 预置 Mirasim、Claude Code 与 Claude 桌面版、Codex（桌面版与命令行）、Google Antigravity（反重力）、CC Switch（接口中转）、Claude 网页版、ChatGPT 网页版、Gemini 网页版。
  - 也可以「添加网址」（填域名，例如 `perplexity.ai`）或「添加程序…」。
- **怎么识别**：
  - 桌面程序按程序识别，它访问的网址都随之走；
  - 网页版只匹配浏览器（Chrome、Edge、Firefox 等）访问所列网址；
  - 自定义网址对所有程序生效。
- **Mirasim 要勾两项**：Mirasim 的助手由 Claude Code 执行，要让 Mirasim 走香港，Mirasim 和 Claude Code 两项都要打开。
- **经本地中转的助手**：如果 Codex 或 Claude Code 的接口地址指向本机（例如 `~/.codex/config.toml` 里 `base_url = "http://127.0.0.1:…"`，由 CC Switch 提供），真正出网的是中转程序，要同时打开「CC Switch」；其他中转程序用「添加程序…」加入。
- **DNS**：名单走交易线路时，名单网址经交易线路解析 DNS，避免拿到被污染的地址。
  - 名单以外的网址仍用本地 DNS。桌面助手访问名单以外、在本地被屏蔽的网站可能失败。
  - 遇到时把该网址加入名单，或临时把「日常上网」切到「走交易线路」。
- **对交易没有影响**：名单规则排在交易规则之后，无论名单怎么写，都不会改变 NinjaTrader、TradingView、Tradovate 的走向，也不会把 BatVPN 自身放进隧道。
- **立即生效**：切换和改名单都立即生效，不重启通道；走向发生变化的助手会自动重连一次。
  - 「日常上网」从「走交易线路」切回 BatVPN 或本地直连时，名单内的助手本来就留在交易线路，连接保持不断，正在进行的对话不受影响。
- **全局模式下锁定**：「日常上网」选「走交易线路」时，所有应用都已走交易线路，AI 助手这一行随之锁定。
- **注意带宽**：助手与交易共用服务器带宽。一般对话流量很小；大文件上传、Antigravity 下载扩展会占带宽，交易时段请留意。

### BatVPN 与本工具同时运行

- 保持 BatVPN 的白名单（或全局）模式，**不要开启 VPN（虚拟网卡）模式**。
- 通道运行期间由 TradeChannel 统一管理系统代理：BatVPN 或其他程序打开的系统代理会被立即暂停，断开通道后恢复。这是预期行为，不会中断交易连接。
- 交易时段尽量不要在 BatVPN 里切换节点或模式；大文件下载、视频会占用本地宽带，可能拖慢行情。

### 升级线路配置（从 0.4 / 0.5 升级）

旧线路配置会在概览页提示「线路配置可以升级」。退出整个 NinjaTrader 后点「升级」：会生成新配置并通过检查，再重新连接（约 15 秒）；原配置保留用于回退。

新版服务商配置要求 v4；升级会中断所有依赖通道的连接，包括 AI 助手，请安排维护窗口。现有 v3 的 AI 助手名单继续可用。之后切换 AI 助手、修改名单和切换日常上网都不需要重新连接。

### 手动断开和再次连接

1. 在概览页点击「断开」，阅读影响后点「断开通道」。订单与持仓由你先行核对，工具不会取消订单。
2. 页面先显示「正在断开」，清理完成才显示「已断开」。不会自动重连。
3. 普通网络恢复；NinjaTrader 的持久阻断继续保留，因此它此时不能直连外网。浏览器没有同样的整进程保护。
4. 下次点击「连接」重新建立通道。若要彻底退出本方案，先退出 NinjaTrader，再到「设置 → 维护与恢复 → 解除 NinjaTrader 保护」。

### 重启、关闭窗口和退出有什么区别

| 操作 | 结果 | 下次怎么继续 |
|---|---|---|
| 窗口右上角 × | 收起到托盘，连接继续 | 双击托盘图标或再次打开软件 |
| 托盘「退出界面」 | 只退出控制台，连接继续 | 再次打开软件读取当前连接 |
| 概览页「断开」 | 通道停止，保护保留 | 手动点击连接 |
| 电脑重启 | 旧网络会话结束，不自动重连 | 打开控制台，连接并检查，再开交易软件 |

「设置 → 登录 Windows 后打开控制台」默认关闭。开启后仅在当前用户登录时打开界面，绝不自动连接或下单。此功能需要管理员账户，产品会把校验过的界面文件放入受限目录，由该用户的登录任务启动。已有节点可能引用原解压位置的引擎，请保持解压目录固定，不直接删除或移动。更新版本后可取消再勾选，以更新登录副本。删除登录任务不解除交易保护。

状态显示会核对系统启动时间、真实进程和控制接口。重启后遗留的运行记录不会继续冒充已连接。遇到「连接需要处理」，按主按钮「重新检查」「断开」或「重新连接」处理；界面无法确认状态时不会偷偷再启动一个通道。

## 7. 看到错误怎么办

| 提示/现象 | 下一步 |
|---|---|
| 请先退出 NinjaTrader | 退出整个控制中心，仅关图表不够；不要强制关闭带有未处理订单的会话 |
| WireGuard 旧隧道还在运行 | 在旧 GUI 点停用；保留软件和导出，不卸载 |
| 密钥/配置格式无效 | 重新从有效 WireGuard 客户端导出，不从截图抄私钥 |
| 服务器公钥等于客户端公钥 | 导入材料有误，需要服务器那一端的公钥 |
| 服务商端口没监听 | 先连接 BatVPN 的节点；网页代理开关不等于核心连接已经就绪 |
| 「已暂停其他程序设置的系统代理」 | 通道运行期间统一管理代理，交易连接不受影响；断开通道后恢复原设置 |
| 「检测到其他虚拟网卡」 | 关闭 BatVPN 的 VPN 模式或停用旧 WireGuard 隧道，避免争夺路由 |
| 日常上网显示「暂时直连」 | 按提示连接 BatVPN 或释放被占用的端口；恢复后自动切回 |
| AI 助手显示「升级线路配置后可用」 | 退出整个 NinjaTrader，在概览页升级线路配置 |
| 助手走交易线路后，某个网站打不开 | 把该网址加入「AI 助手名单」，或临时把日常上网切到「走交易线路」 |
| 登录正常，历史图表很慢 | 检查 HDS 历史服务，不将网页连通当作完整行情正常 |
| 候选出口检查失败 | 查看当前状态和备份；旧节点未删除，不继续叠加配置 |
| 云服务器 ping 通但不出网 | 分别检查 NAT、转发、云安全组与实际 HTTPS 出口 |
| 切换提示缺少分流模式／旧版 mode read-back 报错 | 当前引擎可能只声明了 global。先更新至 0.7.3，再在维护窗口重新生成并加载配置；仅关闭 Clash 或重启原配置无效 |
| 服务商显示「已应用 · 端口未就绪」 | 「已应用」仅表示配置已纳入。启动该客户端、关闭其 TUN，到线路页重新发现/检查；不会因服务商未运行就重启香港 |
| 文件校验失败 | 完整重新解压原始包，勿混用不同版本文件 |
