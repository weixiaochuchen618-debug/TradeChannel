# TradeChannel 0.16.10 首次接入与状态提示修复

- 首次服务器身份确认保存为明确待办；页面持续显示目标和 SSH 指纹，关闭弹窗后可再次打开。首次信任使用独立入口，不误入已有服务器身份更换流程。
- 新登录尝试登记时立即读取真实结果，处理“登记完成前已收到指纹或失败”的情况，清除上一次接入的过期错误。
- 登录中、等待用户确认、密码认证失败及连接超时分别呈现；已经结束的尝试不会继续显示“正在核对”或残留“正在恢复连接”。页面说明单次连接超时及自动重试上限。
- 确认回调绑定原任务、会话、服务器地址和显示指纹；目标、指纹或会话变化时拒绝旧回调。关闭弹窗不登录，同一有效会话再次打开可使用原内存凭据。
- 重试保留原远端未知结果、本机候选失败及已完成进度。等待身份不是部署成功，当前线路不因处理接入而切换。

本轮修复由可使 0.16.9 失败的回归、真实 WPF 页面和本机回环 SSH 验证覆盖。此前候选配置生成失败仍作为独立问题保留，不能据此宣称完整 VPS 部署已经通过。

## 0.16.9 历史变更

- 修复 Worker 和 GUI 重复更新完成回执时，文件占用导致异常穿透界面的问题。先保存终态再发布结果，界面优先消费已有终态，后台有界重试本机记录写入。
- 已取得的失败结果立即更新页面；持续文件占用保留原结果，不把已知结果退回未知，也不自动重发服务器变更。
- 部署失败显示“部署已停止”、实际失败阶段与继续原任务入口。恢复登录页保留失败说明，恢复草稿时先填充原地址、账户、端口及已保存选项，避免异步空表单覆盖。
- 部署状态和候选库原子写入重试短时共享冲突；读取状态允许原子替换，正常轮询不再阻碍写入。真实的持续占用仍明确失败并保留旧状态。
- 原候选配置生成失败保留服务器授权与事务，恢复从原任务继续；新增私有结构化诊断，保存错误类型、错误码和代码位置，不保存异常原文或凭据。
- 控制台运行中断提示恢复原记录；“重新解压”仅用于启动阶段实际发现的包缺失或完整性错误。

本版优先恢复被阻断的体验。未保存的旧密码无法自动恢复，任务凭据续接与取消第二次准备确认尚未纳入本版。安装、完整 VPS 部署和业务连接验收分别记录，不能用隔离验证代替真实部署成功。

# TradeChannel 0.16.8 部署记录与从零体验修复

- 将“已登记服务器”明确为“管理已识别服务器”：只展示具备完整管理地址和应用身份的有效服务器，入口数量与管理列表使用同一来源。无地址空壳不再显示成邀请；真实邀请保留在线路的权限详情中。
- 删除记录、删除线路和服务器资料清理统一进入完整本机清理预览。按服务器身份及完整 SSH 地址关联任务、配置、独占凭据、检测缓存和回执，同一地址的旧身份一并列明。确认后永久清理，旧版“恢复显示”不恢复已清理资料。
- 当前连接、未完成事务、活跃执行器、未释放探针以及其他服务器仍引用的资料受到保护。提交前重核范围和摘要；失败回退，中断后提供本机恢复入口。清理不登录或卸载服务器。
- 阻止仅有指纹的过期回调创建空白服务器；已删除的旧标识不能重新登记。同一地址重新添加会建立新任务和新身份。
- 对特定的旧版 DeploymentAccessState 本机登记失败核验原结果、执行进程和事务归属，记录失败处置后解除无关的全局阻断，不将真实未知变更标为成功。
- 阻断提示显示“尚未提交”、具体记录编号和直接处理入口；无归属回执拥有独立核对页。
- 补齐清理完成但后台结果丢失、清理回退后回执仍未解除、恢复回执丢失等路径；用原确认和持久日志核验，不把未核对的远端部署视为成功。清理同时处理只按操作编号关联的执行器缓存、未完成的回执写入和旧隐藏记录的单项提交索引。
- 同步更新随包指南中的删除范围、不可恢复性及“管理已识别服务器”的用途。安装更新仍只替换程序；清理既有本机部署资料由独立的预览和确认操作执行。

## 0.16.7 已有行为：多轮检测证据修复

- 修复汇总比较编号与最后一轮探针凭据编号混用，导致真实 TCP 成功结果被误报为 `ConfigurationChanged` 的问题。
- 每轮探针分别核对正式配置和清单哈希、临时配置哈希、探针编号及网卡绑定；比较编号、协议顺序、缺失轮次与重复回执也需一致。
- 更新比较回归用例，覆盖真实探针使用的派生凭据格式，以及任意一轮被改动时拒绝推荐的情况。单次探针、旧格式证据、真实超时和可选网站验证保留各自含义。
- 包含 0.16.6 的管理初始化中断续接修复。沿用既有 Linux 网络资源，不增加网络调参或自动启用线路。

## 0.16.6 管理初始化中断续接

- 增加只读 `management_recovery_state`。服务器在共享锁内核对原计划摘要、目标身份、配置修订号、计划过期和管理文件缺失；未过期、部分初始化、配置变化或未决事务均不能解除恢复。
- 原计划未生效的核对还验证原设备授权、UDP 健康和最终服务器状态。结果保存为 `NotApplied`，原意图、原计划及证明进入历史记录；不会将旧操作标为执行成功。
- 核对通过后停在继续检查点，撤销旧计划的批准。新计划经过原有预览和批准入口执行，原设备及隧道密钥保持。
- 界面区分已生效和未生效的核对结果；两种结果均绑定原操作后解除相应等待记录，其他事务和本机探针清理继续保留。

此版本保持 0.16.5 的 Linux 网络资源格式，不增加网络调参或自动切换线路。源码测试、完整包和原中断服务器的现场结果分别记录在交付报告中。

## 0.16.5 已有行为

0.16.5 修复部署恢复与向导隔离问题：

- `apply`、`authorize`、`management_apply`、`transport_apply` 分别核对原变更意图、已认证会话、计划、设备和服务器状态。公钥存在或 UDP 正常不再单独视为变更完成。
- 管理初始化核对检查未决事务、配置健康、完整公钥字段和修订号；始终更新已认证服务器台账及运行快照。TCP 核对还检查生效计划、配置修订号、原设备参数和最后一次服务器状态。
- 增加只读“核对服务器状态”入口。每次核对最多读取 5 个结果，期限 3 分钟；证据不足停在具体问题，不自动循环。核对成功停在可继续检查点，保留其他恢复事项。
- 新建与恢复使用独立向导实例，异步结果绑定原运行和会话；前置参数错误在派发前拒绝，避免误报结果未知。未决操作按已核实的服务器范围限制冲突任务。
- 登录问题、恢复动作和技术详情提供明确入口，部署表单的主操作固定在可见底部。
- 保留已发布的网络资源格式，修复旧部署被实验性资源生成器误判为漂移的问题。未完成回退与实测的 BBR、缓冲及 ICMP 修改未纳入本版。

本版验证范围见交付报告。程序升级、原中断服务器的实际恢复及生产连接验收分别记录；安装程序继续要求旧程序和网络引擎退出。

## 0.16.4 已有行为

0.16.4 基于 0.16.3。连接、配置补全、后台等待和恢复入口共同使用明确的原线路与连接方式；保留交易软件运行保护、身份与哈希核对，以及切换失败后的原连接恢复核验。

- 已保存的有效 UDP/TCP 选择，不再因缺自动推荐证据、可选网站验证或未使用的备用协议失败而被一并禁用。真实身份冲突、配置损坏和未清理任务仍需处理。
- 修复相同连接选择在预览与提交之间被误判为已改变、要求重复预览的问题；真正改变线路、配置或分流选择时仍需重新预览。
- 缺默认时选择已有连接方式；缺配置时定位原准备步骤；旧固定地址或网卡改名时提供本机网络更新预览，完成后回到原连接预览。
- 重试检查使用独立临时探针，不替换正式配置或清除默认选择。网络策略更新生成新版本，保留原版本和配套默认绑定，并提供回退入口。不会在后台批量迁移线路。
- 监督进程区分网卡正常、确定缺失和读取不确定。短暂读取异常使用独立接口证据复核；持续无法核验时保留交易保护并受控停止。
- 后台读取有期限，用户请求可排队；变更结果未知时保留原请求和核对入口，不自动重复执行。界面刷新保留编辑、选择和密码控件。
- 正常状态读取使用随包编译组件、按需模块与复用快照。服务商缓存仅包含展示摘要，配置变化后失效；实际连接和修改重新核验原始数据。
- 打开中断部署只查看；空闲离开关闭管理会话，进行中可返回列表或请求当前步骤完成后暂停。新凭据优先及有界重连保持。
- 系统代理修改先保存持久恢复记录。会话结束后按当前值核对恢复；用户后来修改的设置进入选择入口，不直接覆盖。
- 包安装器验证文件、版本、专用目录和权限，并保留程序回退备份。状态记录采用无损紧凑写入；接近 4 MB 上限会在运行报告提示。

0.16.4 当时未包含服务账户降权、软件包管理器锁处理和历史文件物理清理；该历史版本的删除仅清理展示。0.16.8 的本机物理清理行为以上文为准。

实际 DHCP 换址期间的转发恢复取决于网卡和引擎的现场表现；未完成物理演练的场景不承诺零中断。最终验收范围以交付记录为准。
