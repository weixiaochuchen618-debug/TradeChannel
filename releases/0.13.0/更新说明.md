# 0.13.0 预览版更新说明

基线：0.12.0。标准部署一次备齐 UDP/TCP，日常切换直接使用已保存配置。

- 同一服务器、同一设备、同一线路准备两种连接方式。部署页的 Auto/Udp/Tcp 选择表示初始偏好，标准流程仍准备两种方式。
- 区分配置完整、部署部分完成和需要恢复。TCP 准备失败保留 UDP 成果，在向导内继续完成，或明确选择先使用已准备方式；不显示双协议完整成功。
- 部署后进行三个串行、交替顺序的配对轮次，保存原始样本、逐目标成功/超时、响应时间和路径/出口证据。总量最多42请求，每请求最多6秒；检查可以停止。
- 推荐先核对可达性和证据资格。两种都合格时，仅在每个必需目标至少9对样本、三轮方向一致、配对中位优势同时达到20毫秒及20%时采用质量推荐；相近、样本不足或目标意见不一致时使用明确的UDP策略默认。此为工程初筛，不是交易延迟或长期稳定性证明。
- 推荐摘要绑定配置、引擎、网络、测试时间、配对数据和策略版本，拒绝过期或被修改的结果。用户明确选择优先，运行中不静默换线。
- 日常连接失败不再进入补充部署。切换已准备的UDP/TCP只执行本机受控重连、出口检查及失败恢复；旧线路维护入口独立。
- Linux服务端授权返回MTU，客户端导出、加密交接、TUN、WireGuard和独立探针一致传递并严格验证。旧无MTU返回继续兼容，不自动猜测或改现用配置。
- 旧线路管理查询同时返回已核验MTU；维护以新不可变配置准备UDP/TCP，保留原配置、设备身份和正在使用的连接。
- 窗口偏好读取直接打开文件并按实际错误分类，避免原子替换时将短暂共享冲突误当缺失；持续占用仍报告错误。

新增设备接入无需服务器管理凭据。管理端应先完成服务器双协议准备，授权资料才会包含两套连接参数；旧服务器仅提供UDP时，接入页诚实显示部分完成，普通客户端不会擅自取得管理权限或安装服务。

新增带MTU的授权资料应由0.13.0客户端处理；新版同时接受旧的无MTU响应。实际服务器、物理网络、系统TUN接管和交易业务验收范围以交付报告为准。
