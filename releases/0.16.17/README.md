# TradeChannel 0.16.12 预览版

本版修复首次身份确认后重连再次询问、自动默认协议读回失效，以及单线路删除扩大到同服务器其他线路的问题。任务内明确确认在同目标、同指纹下固定有效 30 分钟；长期 pin 与身份变化核验继续保留，修改密码不重置有效决定。

执行器回执保留最多 128 条脱敏事件、最后接入失败及重试关联标识；正常关闭保留此前失败原因。明确确认的引用和收到已有 pin 分开记录，诊断元数据不参与授权。管道提前失败时保留原错误并清理凭据副本。

线路页统一显示 UDP/TCP 配置和检查状态。点击协议胶囊仅保存下次默认，当前连接保持；点击连接或切换才进入连接预览与确认。更多菜单提供详情、服务器与设备、改名、回退和删除独占本机资料；使用中的线路不可删除。

完成部署从待办移出；检查失败、过期或默认来源问题在线路管理处理。真实未决事务继续保留恢复。旧默认仅在原摘要、配置身份和探测证据完整时修复，证据不足时重新选择已准备协议。

连接事务预算：正常连接／换线 120 秒，单次验证最多 45 秒，失败恢复独立 90 秒；外层监督 240 秒涵盖恢复和收尾。阶段来自实际事务。恢复未知保留 NeedsRecovery，不宣称原线路已恢复。部署双协议比较保留独立预算。

完整包需通过安装器安装。本轮不安装真实环境，不登录或部署真实 VPS，真实网络与交易体验由用户继续操作。

## 0.16.11 已有行为

本版修复登录失败后修改密码时，旧失败轮询反复清空新输入的问题。修改页持续显示失败原因和目标；密码及私钥解密口令可以显示／隐藏，切换保留输入和光标。提交后、离开页面或窗口失去激活时恢复隐藏；服务器未给出具体原因时，不将认证拒绝直接归因于密码错误。

连接中、等待确认、登录失败和连接超时分别显示实际状态。单次 SSH 连接超时为 20 秒，自动重试最多 2 次；重试停止后提供手动重试或修改登录资料入口。开始重试只清除过期接入错误，不清除原部署的未决事务和本机业务失败。登录会话结束或内存凭据过期后，回到原任务的登录页并说明原因。

填写地址与登录资料后点击“部署这台服务器”，正常范围内自动推进环境检查、UDP/TCP 准备、本机授权与配置保存；首次身份或身份变化仍有明确确认。默认勾选“任务期间记住登录，完成后清除（最长 24 小时）”，使用 Windows 当前用户加密。重新打开任务保留地址和协议偏好，点击继续后才使用有效保存资料；新输入或新选择的密钥优先。

候选库现允许软件自己生成的 display-cache 目录，修复该目录导致候选生成失败的可重复阻断。失败记录保留具体业务步骤、字段规则、原始来源和工具退出码；不保存异常中的密码、密钥或配置原文。候选已入库但任务未发布时，恢复使用同一个候选。

失败页提供“放弃本次准备并清理本机资料…”。先核验实际执行器、预览关联范围，空闲执行器正常关闭最多等待 5 秒；活跃远端操作及当前线路仍受保护。远端结果未知时可明确只放弃本机跟踪，服务器现状保留。历史中的旧运行标签不再永久封死清理入口。

远端缺 Python、sudo 权限不足和发送中断分别分类，SSH 载荷发送等待有 30 秒上限。Linux 安装支持原 IPv4 转发值为 0 或 1，并在回退时恢复原值。

完整服务器部署及业务连接是否成功，以用户实际操作后的日志为准。本机和回环验证不替代真实 VPS 验收；安装只更新程序，保留线路与当前部署任务。

## 0.16.9 已有行为

本版修复部署完成回执处理中的并发异常：执行器先保存终态再发布结果，界面消费已有终态回执；回执短时占用时延迟重试，已取得的业务结果仍立即显示，不能因本机文件异常让整个控制台退出。重复回调不重复执行，持续占用保留原结果供恢复。

部署失败明确显示“部署已停止”、实际步骤与继续原任务入口；重新打开需要登录的失败任务也显示原停止阶段，并恢复服务器地址、账户、端口和已保存选项。运行中异常不再误报“重新解压”，会记录不含密码、私钥和配置原文的结构化诊断。部署状态与候选库原子写入针对短时共享冲突做有界重试。

0.16.9 解决回执与停止提示；0.16.11 增加任务期凭据保存和正常范围的自动推进。此前未保存的密码无法恢复，需在程序中补录一次；不会自动切换当前线路。

## 0.16.8 已有行为

本版统一部署记录的生命周期。服务器管理只列出有完整管理地址和应用身份的服务器，入口数量与列表一致；未完成的准备保留在部署中心，真实邀请接入在线路详情中保留使用权。仅有指纹的过期回调不能创建无目标记录。

“删除记录”与线路删除统一进入本机部署资料清理预览：按服务器标识及完整 SSH 地址关联新旧身份、任务、配置、凭据、检测缓存和后台回执；保护当前线路、共享资料、活跃执行器以及未核对的远端变更。提交前重查，发生文件错误回退，中断后在部署中心恢复。清理不登录、不卸载服务器。旧版软删除单独标为“显示旧版隐藏记录”，真实清理没有恢复显示入口。

兼容处理旧版没有 RunId 的 DeploymentAccessState 失败回执：只有原结果匹配、执行器退出且无远端或网络事务绑定时，才记录为本机登记失败并解除阻断。其他未知操作保留核对要求；阻断提示直接显示具体操作并提供处理入口。

本机清理或恢复的后台结果丢失时，以原确认与持久日志核对完成、回退或尚未生效；恢复文件后同步处理原回执，避免再次形成全局阻断。删除覆盖程序用于接入和续接的台账与缓存；其他线路的历史观察快照、人工备份和诊断归档保留，不按 IP 批量删除，也不作为新建部署的来源。

本版修复多轮独立检测被误报“配置已变化”的问题。比较结果与每轮探针分别校验各自编号，逐轮核对正式配置、临时配置、网卡绑定与原始回执；失败或超时仍保留在结果中。基础 HTTPS 全部通过的方式可正常获得可达性推荐，可选网站要求人工验证不会单独否定基础连接。

管理初始化中断后，除核对已生效结果外，本版还能确认原过期计划当前未生效。核对绑定原计划摘要、服务器身份、配置修订号和原设备，要求没有未决事务且管理状态、私钥和公钥文件全部不存在。通过后保留原记录为 `NotApplied`，停在可继续检查点；继续时生成新计划并重新确认，不重放过期计划。存在残留或曾登记过管理身份时仍保留恢复状态。

本版修复部署结果未知后的核对流程，以及新建向导被旧会话回调影响的问题。安装、授权、管理初始化和 TCP 增量提交分别按原计划与原身份读取实际结果；核对成功先保存检查点，点击“继续原部署”后再推进。核对失败显示具体原因，不自动重复提交。服务器管理台账与部署记录一起保存，其他未完成事务和本机探针清理仍需单独处理。

网络资源继续采用已发布的旧格式，兼容原有部署及事务日志。本版不启用实验性的 BBR、缓冲调优或宽泛 ICMP 放行；已经在服务器上手工改动的资源仍按漂移检查处理。核对不等于业务连通性测试，正式启用前仍遵循原连接验收。

完整解压到固定目录后运行 TradeChannel.exe。完整包内置运行组件和 Framework 依赖，不需要分别安装 WireGuard、sing-box 或 Python。打开管理界面只读取状态，连接、断开和换线由用户明确操作。

部署入口统一为“添加线路”：提供服务器资料，或粘贴/打开邀请、公开申请和加密授权。软件判断电脑是否已准备、服务器是否已部署及当前资料属于哪一步，不再要求普通用户先选场景。

服务器准备在同一向导内串联环境检查、UDP/TCP 准备、本机授权、配置生成、独立检测和结果保存。TCP 未完成明确显示部分部署，主操作继续完成；自动保存不代表验证通过，更不会自动启用。云平台权限缺失时给出实际端口清单，不能代替用户放行云规则。

登录错误和服务器重装在当前步骤处理。SSH 主机身份与隧道应用身份分开核对：同指纹也能发现应用重置，仅主机密钥变化时保留原应用授权。新目标和变更范围需要对应确认，原批准不能跨身份使用。

同一次准备中的 SSH 断线会优先复用有效登录信息，最多自动重连两次；从部署中心重新打开中断的运行只显示进度，继续远端步骤需要明确点击。“重试连接”和“修改登录资料”分别提供，修改登录资料时新输入的密码或私钥优先于已保存凭据。页面显示中断步骤和已保存配置。只有认证拒绝、凭据过期或缺少可用凭据时才要求重新填写；服务器身份变化仍需核对。可能已执行的变更先核对结果，不重复部署或授权。

已保存的默认连接方式与本轮短期推荐分开。普通检查失败、推荐过期、可选网站验证或备用方式未准备，不撤销完整配置的有效用户选择；点击显示协议的连接按钮后，仍校验配置、身份、未完成事务、NinjaTrader 保护和实际出口。缺少默认时先选择已有连接方式；身份冲突、配置损坏或残留进程继续阻断。正在使用的设备身份不会被并行探测。

旧版线路保留已选择的默认方式，包括升级前已正常使用的香港主线。旧配置需要更新本机网络策略时，连接入口定位原线路并显示预览；更新生成可回退的新版本，随后回到原连接预览。换线前与实际出口检查共用 UTF-8 配置读取和本机入口、网卡检查；失败提示区分失败原因与原线路恢复结果，不显示配置原文或密钥。

重新检查使用独立的探针副本，并绑定本轮本机网络与证据；正式配置、默认选择和历史检测结果分别保留。网络更新后的正式配置约束在选定物理网卡，不长期保存 DHCP 源地址。会中实际换址仍需现场验证，软件不会自动改走其他交易出口。

状态读取与服务器管理等待在后台执行，界面保留输入、选择和原操作。读取超时保留最后可信状态；已提交操作结果未知时提供原请求的核对入口，安全断开仍可执行。窗口退出时释放读取进程；“稍后继续”关闭空闲管理会话，忙碌时提供返回列表或等待安全检查点暂停。

部署中心按“需要处理”“继续准备”“已保存草稿”显示每一次添加；已保存配置从对应线路打开。草稿只指尚未执行部署、没有授权或恢复依赖的填写资料，可以“放弃本次添加”，之后从操作历史恢复填写。旧版未知任务只打开记录详情，不会因查看而恢复执行。

“线路”提供服务器管理总表；每条线路的“服务器与设备”直达它关联的服务器，管理设备、补全部署或核对服务状态。缺失、多个或已归档的身份关联会说明原因，不按相同 IP 推测目标。仅有连接使用权的电脑不会显示服务器写操作。

“操作历史”支持单条删除、多选删除和全选当前筛选结果。部署中心和服务器管理也提供本机资料清理入口。确认页列出关联服务器身份、操作、线路配置、文件及保留项；一次清理可能包含同一管理地址的新旧身份和多条记录。确认后永久清理对应的本机部署资料，不能通过“显示旧版隐藏记录”找回。旧版隐藏记录仍可恢复显示，尚未执行部署的草稿仍可“放弃本次添加”并恢复填写。当前线路和真实执行中的操作需先处理，再重新预览；远端结果未知可另行明确只放弃本机跟踪。

购买准备、迁移到新电脑、Windows Server 部署和管理恢复资料导入在部署中心顶部直接可见。

新电脑只显示当前接入步骤。管理端仍需批准独立设备身份，加密授权交回原申请电脑后自动保存候选配置。授权中的服务器出口证据用于确定探针验收目标；本机可用性仍需独立检测，不由服务器状态代替。

概览、窗口、任务栏徽标和托盘同步显示通道状态。“检查出口”、NinjaTrader 登录/行情/订单和 AI 平台地域支持分别验收。关闭方式在设置中选择；收起到托盘或退出界面保持后台连接，重启电脑后需手动连接。
