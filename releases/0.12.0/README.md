# TradeChannel 0.12.0 预览版

完整解压到固定目录，双击 TradeChannel.exe。打开管理界面读取现有状态；连接、断开和更换线路由用户明确操作。

首次部署默认在同一次向导中准备 UDP、尝试准备 TCP 备用，并自动检查已准备的连接方式。通过可达性资格核对后，保存这台电脑下次连接的默认方式。性能数据用于展示，本版不做性能排名或运行中静默换线。

部署结束后：

- 有合格推荐：点击“连接推荐方式”，核对预览后连接；也可以稍后使用。
- 明确指定 UDP/TCP：保留手动选择，检查结果单独显示。
- 两种失败、身份在用、路径无法核对或证据过期：说明原因，不把失败方式兜底为默认推荐，保留已准备的服务器和本机资料。

日常选择一条线路即可。UDP/TCP 是同一线路的连接方式。连接方式页中的默认值只影响下次连接；更改默认值不会切换现有通道。旧线路在首次点击连接时自动整理本机连接资料，不重新部署服务器或新增设备。

线路卡优先显示实际正在使用的方式和本次会话检查结果；失败、结论不足、身份阻断和历史过期分别显示。“连接检查”通过后直接继续使用，不因检查失败统一要求补 TCP。“补齐备用配置”只用于确有缺失的旧线路。

探针采用独立用户态引擎和本地认证入口。正式配置与探针保存相同的外层网卡和 DNS 绑定；观察条件不满足时不冒称物理直连。在用 WireGuard 身份不能另开候选探针，避免影响现有连接。

推荐与服务器/设备身份、连接方式、配置与引擎完整性、网络环境和时间绑定。网络或配置变化后重新核对；有限 HTTPS 样本不表示裸 RTT、真实丢包率或长期交易稳定性。

实际启用使用受控事务：核对预览、停止原会话、启动目标、验证出口，失败按原状态恢复并复测。配置还原不等于连接或交易软件业务恢复。请先退出整个 NinjaTrader 再切换；行情、登录与订单需在交易软件中核对。

部署需要对应服务器权限与云端入口规则。购买、云账户操作和新线路启用由用户明确确认。新增电脑使用独立授权与加密交接，不复制另一台电脑的身份。
