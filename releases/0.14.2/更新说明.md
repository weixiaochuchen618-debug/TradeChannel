# TradeChannel 0.14.2 部署检测闭环修复

- 修复自动协议对比未准备检测网卡绑定的问题。UDP/TCP 使用实际外层与 bootstrap DNS 绑定，生成新候选后重新读取 revision/哈希，再执行既有三轮交替检测。
- 分别展示配置完整度、网络检查、默认建议和启用状态。没有推荐时给出原因与下一步，支持检测网络选择、诊断摘要及已准备方式的手动试用。
- 完成页增加“完成，保留当前连接”。默认建议不启用系统隧道；日常选择只使用保存的 UDP/TCP 配置，切换仍须退出 NinjaTrader 并明确确认。
- 旧检测尝试保留为历史；网卡、配置、时间与出口证据必须相符。可选网站的人工验证或地域限制不影响隧道资格。
- 部署页和线路页复用同一检测流程。本机重新检查沿用原设备身份和授权；活动身份冲突、探针清理未核实或事务未知时保持阻断。
- 本机探针恢复与服务器事务恢复分开处理。恢复只清理已核实结束的拥有实例；存活或身份不明的进程不被停止。
- 已登记服务器重装支持受控的新 SSH 身份核验。认证与指纹确认通过后原子建立新记录、归档原身份；旧任务、设备授权和保存密码不能自动继承到新服务器。
- 保留 0.14.1 的任务栏状态徽标、托盘颜色、关闭偏好、分流管理及连接恢复保护。

三轮 HTTPS 样本用于本轮可达性及响应比较，不代表交易延迟、长期稳定性或 AI 平台业务可用。真实启用后仍需分别核对交易登录、行情和历史数据。
