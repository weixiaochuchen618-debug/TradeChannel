# TradeChannel 0.10.0 新手指南

## 打开软件

完整解压到固定目录，运行 TradeChannel.exe，按提示允许管理权限。不要从 ZIP或临时目录运行，不要只复制 EXE。创建桌面入口可指向此完整目录。

打开界面不会自动连接或换线；已有通道继续使用，新增线路先准备候选。

## 第一次配置

1. 部署 → 第一次配置，没有服务器时先查看购买准备。
2. 准备 Ubuntu 24.04 / Debian 13 x64 专用 VPS、公网 IPv4及管理员接入资料。
3. 粘贴 IP、root@IP或支持的 SSH说明，核对账户和地址。
4. 在界面输入密码；用密钥时填文件及口令。核对首次主机指纹，已知指纹变化时停止确认。
5. 环境通过后查看计划，在云平台放行本次端口并保留 SSH。
6. 确认执行，软件部署、授权并导入。
7. 独立测试候选，看 DNS、转发、出口和路径结果。
8. 显示“尚未启用”后，安排时间到线路/概览明确连接。

非 root需已有非交互 sudo；软件不改 sudoers。缺少依赖或发现外部环境时按具体提示处理，不自动覆盖。

## 新增、更换或续接

部署 → 接入新服务器，旧线路保留。使用偏好可继承，服务器身份与认证重新取得，不只修改 IP。

关闭界面后从未完成操作续接原运行。结果未知先查询原事务/申请，不反复创建授权。已有 UDP 服务器可在维护页预览新增 TCP，不能靠覆盖安装完成。

## 新增电脑

1. 管理端：我的服务器 → 登录管理 → 生成邀请。
2. 可信交给新电脑，核对管理端显示的签名身份。
3. 新电脑：连接已有服务器 → 粘贴邀请 → 确认身份 → 生成申请。
4. 管理端核对申请/配对码并批准。
5. 加密授权交回新电脑，新电脑完成合成和导入，再独立测试和明确启用。

不复制旧电脑私钥同时使用。新电脑无需 SSH密码。邀请丢失可从已登录管理端按 ID恢复；授权结果丢失查询原申请，不新增 Peer。

## 维护与恢复

设备可查询、命名、撤权；当前使用身份/服务器需要先安排维护。撤销一台不应影响其他设备。

部署完成后建议导出管理恢复资料。只含记录不含凭据的包不能单独恢复登录；设置迁移只是偏好。恢复导入不自动启用。

概览运行状况查看时间轴和来源，导出 JSON及文字摘要。托盘仍观察异常，不自动切线、重启或操作交易账户。

线路 → 还原配置，先核对旧资料。在线配置需退出交易软件并明确断开，再预览、还原和手动连接。只准备回退候选不改变当前网络，旧文件缺失/哈希变化时拒绝。

## 常见提示

| 提示 | 操作 |
|---|---|
| 主机身份变化 | 核对重装与目标，不忽略 |
| 登录失败 | 核对账户、公钥安装或密码 |
| 原私钥缺失 | 新身份申请，处理旧授权 |
| 结果未知 | 查询原申请/事务 |
| UDP未验证 | 云规则、重测或准备 TCP |
| ExistingSystemRoute/Inconclusive | 外层物理路径未证明，查看分层结果 |
| 网站验证/403 | 浏览器核对，不据此单独判隧道失败 |
| 在线不能还原 | 明确停止后重新预览 |
| 快捷方式旧 | 核对位置，重建本版本入口 |

卸载服务不释放云资源。本产品不检查在线更新或管理云账单。
