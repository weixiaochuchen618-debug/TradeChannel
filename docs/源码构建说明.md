# 源码构建说明

最新版本入口是 `releases/0.16.17/`。项目使用 Windows PowerShell 5.1 与 .NET Framework 4.8 编译器，不依赖 Visual Studio 解决方案。下面的命令都在仓库根目录执行。

## 准备第三方依赖

源代码仓库不包含 EXE、DLL 和安装包。当前构建器对二进制依赖检查固定 SHA256，任意下载一个新版本并不能替代所需版本。

需要准备以下文件：

| 位置 | 来源和版本 |
|---|---|
| `releases/0.16.17/assets/sing-box.exe` | 官方 sing-box 1.14.2 Windows amd64 发行包 |
| `releases/0.16.17/assets/wg.exe` | 对应的官方 WireGuard Windows 分发版 |
| `releases/0.16.17/assets/wireguard-installer.exe` | 官方 WireGuard 安装器的指定哈希版本 |
| `releases/0.16.17/assets/lib/*.dll` | `deployment/dependencies.lock.json` 指定的 NuGet 包、资产路径和哈希 |

官方下载地址及固定哈希见 [第三方说明](../releases/0.16.17/THIRD-PARTY-NOTICES.md)，NuGet 下载地址和每个文件哈希见 [依赖锁定清单](../releases/0.16.17/deployment/dependencies.lock.json)。NuGet 的 `.nupkg` 是 ZIP 格式，可解压后提取清单所列的 `Asset`，放到其 `File` 路径。

如果本机已有可信的同版本完整包，可从该包取得上述二进制依赖；构建器仍会逐项核对哈希与安装器签名。上游下载文件变化时应取得匹配的可信历史文件，或经过独立核验后更新依赖契约，不能跳过校验。目录里的旧 `Sync-Binaries.cmd` 和 `Build-Launcher.cmd` 面向完整发行包，不负责从源码恢复依赖。

## 构建完整包

```powershell
& "$env:WINDIR\System32\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -ExecutionPolicy Bypass -File .\tools\Build-TradeChannelPreview.ps1 -Version 0.16.17 -SourceDirectory .\releases\0.16.17 -OutputDirectory .\dist\0.16.17
```

构建器校验依赖，编译启动器和组件，生成 ZIP 和 SHA256 文件。启动器会核对包清单；修改源码后需要重新构建，不能沿用旧清单。构建输出在 `dist/`，已被 Git 忽略。

## 隔离检查

以下示例只覆盖已知主机条目的隔离处理，可在准备依赖前运行：

```powershell
& "$env:WINDIR\System32\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -ExecutionPolicy Bypass -File .\releases\0.16.17\tests\Test-HostKeys.ps1
```

PowerShell 文件可使用 `System.Management.Automation.Language.Parser.ParseFile` 检查语法，Python 文件可使用 `ast.parse` 检查语法。完整测试中的部分用例需要第三方组件、隔离数据目录、回环 SSH 或专门的网络环境。

不要一键批量执行所有 `Test-*` 工具。`tools/Test-TradeChannelScenarios.py` 等故障演练可能中断真实网络；运行前应读取脚本要求并准备专门的测试环境。此次上传的检查不等于真实服务器部署或生产连接验收。
