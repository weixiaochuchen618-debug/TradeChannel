# TradeChannel 0.23.4-preview：旧线路档案的连接检查兜底

0.23.3 的「更新线路配置」使当前会话通过了连接检查，但本机保存的线路档案仍为策略版本 4。以后断开再连接时，旧档案的域名检查仍可能受本地网关错误应答影响。0.23.4 为这种情况提供连接检查兜底；实际断开后重新连接的产品流程尚需在维护窗口验收。

仅当处于规则模式、出口地址检查通过、域名检查失败，并且检查入口未配置为使用线路内 DNS 时，程序才会通过同一交易出口向 `1.1.1.1` 进行 HTTPS DNS 查询。随后通过返回的公网 IPv4 访问原域名，TLS 服务器名称、Host 和证书验证仍使用原域名。出口地址与域名请求的出口 IP 必须一致；权威出口归属证据存在时仍要求匹配。查询或 HTTPS 验证失败时，连接仍不通过。已将该检查入口配置为线路内 DNS 的配置继续使用原来的检查，不启用兜底。

成功使用兜底时，连接事务的 `TargetCheck.DnsResolution` 为 `InTunnelFallback`，`DnsFallbackAttempted` 为 `true`，`EngineDnsCheck` 留存原域名检查的失败结果。等待原域名检查超时可能使连接耗时增加，整个连接检查仍受原有 45 秒预算约束。

本版不修改已保存的线路档案或线路策略生成器；旧档案仍显示策略版本 4。「更新线路配置」目前不会写回该档案。单独的手动会话检查也未加入此次兜底，不应将其结果等同于连接事务的检查。

维护窗口内完全退出 NinjaTrader，正常断开 TradeChannel，关闭界面，再安装完整包。随后打开 TradeChannel，使用已保存线路在规则模式下连接，核对事务记录、出口和交易保护。首次断开、重连和必要回退会影响现有连接，应等用户安排维护窗口。无需为了此次兜底再次运行「更新线路配置」。

验证：17 个相关回归套件完成且退出码均为 0；`Test-RuntimeBridge` 88 项通过，`Test-ConnectionDiagnostics` 64 项通过，`Test-ConnectionTransactions` 996 项通过。使用现有策略 5 会话对新版探测脚本做只读实测，线路内 DoH 查询及使用其返回地址的域名 HTTPS 检查均返回 200，两个 trace 的出口 IP 一致。旧策略档案的断线重连、重启后的完整产品流程及实际交易业务仍未现场验收。

六个契约版本号不变，服务器端不需要更新。

# TradeChannel 0.23.3-preview 修好「重启后连不上」：连接检查的域名解析改走线路内

这一版只修一处：线路已经通了，却在连接的最后一步被「转发未验证」整体回滚，退回已断开。

## 修了什么

**连接完成前的「域名检查」被局域网网关改写，线路被误判为不通。**

- **现象**：重启电脑后点「连接」失败；把「日常上网」改成「使用交易线路」（全局模式）就能连上。
- **原因**：连接完成前，程序通过一个本机检查入口访问 `1.1.1.1` 和 `www.cloudflare.com`，两项都通过才算线路可用。规则模式下，这个入口查域名走本地 DNS（局域网网关）。这台网关把 `www.cloudflare.com` 回答成 `127.0.0.1`，请求被指回本机，10 秒后超时，域名检查失败。全局模式的域名解析走线路内的 DoH，所以不受影响。独立探测一直走线路内解析，所以探测通过、真实连接失败。
- **修复**：检查入口（仅它专用的用户名）的域名解析固定走交易出口内的 DoH。新增的这条 DNS 规则排在代理软件本地解析规则之后、模式规则之前；交易软件和其他流量的解析方式不变。线路配置版本由 4 升到 5。
- **提示更准**：出口地址检查通过、域名检查未通过时，现在写明「出口地址检查已通过，域名检查未通过」（`LineDomainCheckFailed`），仍整体回滚，不留半连接。出口地址检查失败的提示不变。
- **更新入口**：程序判断已保存线路是否需要更新时，原先写死「低于 4」。现在改为与生成端同一个版本号（5），单元测试守住两处不再不一致。所以版本低于 5 的线路会在「维护 → 配置与程序 → 线路配置」出现可用的「更新线路配置」，首页（降级界面）显示「线路配置有新版本」。

## 怎么更新（需要维护窗口）

1. 完全退出 NinjaTrader（Control Center → File → Exit）。
2. 安装本包。安装不修改线路与偏好，并保留 `C:\tradechannel` 的访问权限设置。
3. 打开 TradeChannel，进入「维护 → 配置与程序 → 线路配置 → 更新线路配置」，点「更新并重新连接」。原配置保留用于回退。

更新前的临时办法：「应用」页 →「日常上网」→「使用交易线路」，再连接。

## 验证

- **隔离引擎复现**（真实 sing-box、本机真实网关，不动现有连接）：旧规则下地址检查 3/3 通过、域名检查 0/3；加入新规则后 3/3 都通过，出口为 `203.0.113.101`。
- **单元与回归**：`Test-NodeStore` 396 项（0.23.1 为 392，新增 4 项：规则唯一且作用域正确、位置、探测与引擎同走线路内解析、两处版本号一致；含 21 次真实引擎配置检查）；`Test-ExitCheckBinding` 17 项；`Test-ConnectionTransactions` 996 项；`Test-SessionState` 218 项（新增「旧版本线路会被提示更新」）。其余相关套件与 0.23.1 基线一致通过；真实引擎的 `Test-ProviderSelectors.py`、`Test-ControllerModes.py` 通过。
- **界面自检**：各结果文件的通过状态与断言数和 0.23.1 一致。`Test-0120UI` 在 0.23.1 上就失败（与本次无关），对照时两边都跳过了它。

六个契约版本号不变，服务器端文件不需要更新。

# TradeChannel 0.23.1-preview 修好「AI 工具名单」的保存按钮

这一版只修一处回归：名单页勾选工具后点「保存」没有任何反应。

## 修了什么

**名单页底部操作条（保存 / 放弃修改）点了没反应。**

- **原因**：网页投影每生成一帧快照，都会先回收「这一帧没见到」的控件句柄，再投影底部操作条。操作条不在正文容器里，于是它的按钮每一帧都被判成「已消失」——句柄连同「控件→Id」映射一起删掉，下一帧再发一个全新的 Id。浏览器点的永远是上一帧的 Id，宿主查不到，返回 `UnknownId`；界面只对另外四种错误码给提示，这个码被静默丢弃，表现就是「点了没反应」。
- **影响**：「保存」和「放弃修改」都失效；正文里的复选框、添加网址/程序不受影响（它们的句柄跨帧稳定）。「返回应用」的拦截走的是另一条消息通道，所以会正常弹「保存并离开」。
- **修复**：投影顺序改为「先投影操作条、再回收句柄」，句柄跨帧稳定；`UnknownId` 补一条「页面已更新，请重新操作」的提示，同类问题不再静默。
- **测试**：`Test-WebForms.ps1` 新增 3 条断言（句柄跨快照稳定、点击可达原事件、只触发一次），267 项全绿。

六个契约版本号不变，服务器端文件不需要更新。

# TradeChannel 0.23.0-preview 登录一台服务器只需一次，之后在这台电脑直接进入

这一版解决「每次登录服务器都要重新输密码」：登录成功时把登录资料加密保存在这台电脑，下次点「用已保存的登录资料」直接进。服务器身份一旦变化，旧资料自动失效并要求重新确认——省掉的是键入，不是身份核验。

## 改了什么

### 1. 登录成功后，登录资料可以留在这台电脑

服务器页的登录卡新增「在这台电脑记住登录资料」，默认勾选。只有在登录成功、且主机指纹已确认之后才会保存；取消勾选则只用于本次登录。密码与私钥口令都只以加密形式落盘，用当前 Windows 用户解密。

### 2. 「部署 → 添加线路」也会记住

以前部署成功后只保留 24 小时的任务资料，过期再进服务器页仍要重新输入。现在部署页也有「在这台电脑记住登录资料」，与原有的「本任务中断后可用这份资料继续（最长 24 小时）」分开：前者长期有效，后者只在任务中断时帮你续上，两项可以分别关闭。

### 3. 第二次登录不用再输

登录方式里会出现「用已保存的登录资料」，点它直接连。它仍然完整执行主机指纹与身份核验，与手输密码走同一套确认流程。

### 4. 服务器变了，旧资料自动失效

保存时把这台服务器的身份一并绑定（记录、地址、端口、账户、SSH 指纹、身份代次、登录方式）。任何一项变化，旧资料都解不开，也不会被拿去静默重试；重装后的新记录不继承旧密码。

### 5. 可以随时删掉

登录方式里新增「删除已保存的登录资料」。删掉后按钮消失、不需要重启，线路与授权不受影响；本机资料清理也会一并回收。

### 6. 网页上生成邀请码不再被卡住

以前网页端只认已保存的登录资料，而这份资料从来没被保存过，于是所有服务器的在线邀请都会被拦下并提示「请到服务器页登录」。现在保存链路打通，网页端可以直接完成邀请——但它仍然不会自己收密码。

### 7. 顺带修好「导出管理恢复资料」

这个功能此前对任何真实服务器记录都会报「交接资料包含未支持字段」——校验清单与实际记录字段对不上。现在可以正常导出，导出内容仍只含跨机器的连接信息，不含本机凭据指针。

## 安全与边界

- 登录资料用 Windows 当前用户级加密保存：拷到另一台电脑、或换一个 Windows 用户，都解不开，需要重新输入一次。
- 同一 Windows 账户下运行的其他程序仍可解密本机文件——这是该保护方式的边界，不是本版的缺陷。
- 界面只显示「登录方式」与「保存时间」，不提供查看或复制密码的入口。
- 诊断导出、操作记录、只读检查窗口、网页响应里都不包含登录资料。
- 保存与删除不写操作记录（它们不是远端变更）。

## 兼容与验证

- 旧版本没有这个字段，读取时按「没保存过」处理，不影响已有服务器记录、线路与授权。
- 新增字段不改恢复包、配对与部署流程的既有校验；恢复包仍默认不含凭据。
- 自动化：真 SSH 回环 74 项、身份过渡与重装保护、清理链路、web 邀请、界面分区与导航测试均通过；24 套回归中 23 套通过，`Test-015PairUI` 因本机临时目录 ACL 前置在 0.22.6 上同样失败，与本版无关。

# TradeChannel 0.22.6-preview 登录路径与设置页的体验修正

本版集中修「点了几次才到位」的交互：登录不再绕路、不再重复信息、说明不再自己收起，设置页不再有假装是开关的徽章。连接、代理恢复、服务器契约与凭据存储均未改动。

## 改了什么

### 1. 「去登录」不再经过线路绑定中间页

以前在邀请页点「去登录」，会先落到标题为「线路的服务器与设备」的加载页——那是「线路与服务器绑定异常」的页面被复用成了加载容器，读完记录才进登录。现在点下去直接进登录：加载中标题是「登录这台服务器」、副标题「正在准备登录…」，读完在同一页出现登录方式选择，不再有第二次跳转。

### 2. 登录前不再等 3–5 秒

原来每次点「去登录」都会启动一个独立 Worker 进程重扫部署中心（`DeploymentDiscover`），3–5 秒全花在进程冷启动和重扫上。而邀请页本来就在界面进程内毫秒级读同一份服务器注册表。现在登录前先读本机记录：命中唯一且未归档就直接进「选择登录方式」，不起 Worker；只有记录缺失、已归档或读取失败时才回退到原来的读取流程。

### 3. 登录卡不再重复标题和服务器地址

页面标题和摘要行已经写着「服务器 <地址> · 未登录管理 · 关联线路 <名>」，卡片里又重复一遍「登录这台服务器」和地址。现在卡片只保留一句「选择登录方式」和三个动作：用已保存的登录资料 / 用服务器密码 / 用 SSH 私钥。

### 4. 折叠说明不再自动收起

「新电脑怎么用」「连不上 18443 怎么办」展开后会被下一次状态刷新（每秒一次）收回去——刷新时把 DOM 属性严格同步成模板，而 `<details>` 的 `open` 是用户当场点出来的，模板里没有它。现在把 `open` 当作用户状态保留：展开就保持展开，自己收起后刷新也不会被重新打开。该修正对所有折叠块生效。

### 5. 「线路变差提醒」改成真正的开关

设置页这一项以前是写死的「始终开启」徽章——设置层只存两个字段（首次服务器身份、登录自动连接），它从来没有实现过存储。现在是正常开关，默认开启，可以关闭。关闭只停「线路响应异常」横幅，质量采集与线路页的质量显示不受影响。旧 `ui-settings.json` 读取时自动补默认值，不需要迁移。

### 6. 每个页面只有一个返回出口

页面自带的返回按钮会提升到标题区上方的面包屑，沿用原控件句柄与返回清理逻辑（不是简单的页面硬跳），文案写目的地——「返回邀请其他电脑」「返回线路列表」「返回服务器与设备」「返回部署中心」。邀请页底部那个与面包屑同发 `Close` 的「返回」已去掉；多台服务器时的「上一步」保留。

## 兼容与验证

- 旧设置文件（只有两项）读取时补 `QualityWarning=True`，无需迁移；写入时会带上第三项。
- 原生 WPF 降级路径（没有 WebView2）行为不变，每页同样只有一个返回出口。
- 自动化：Web 验收 656 条全部通过（含登录直达、返回提升、折叠保持、提醒开关的守护断言）；WPF 导航测试与服务器页分区测试通过；设置与 Worker 契约测试通过；产品自检 33 项中仅 1 项既有失败（自 0.22.3 起存在，与本版无关）。

# TradeChannel 0.22.2-preview 邀请页拆成四屏，入口按线路解析，离开页面不再锁死

本版只处理「邀请其他电脑」这一条链路：入口不再点不动，页面不再一屏两用，返回不再跳错地方，离开页面也不再让功能变成一次性的。

## 改了什么

### 1. 线路页的邀请入口先选线路（问题一）

- 以前标题栏按钮不带线路，宿主要求「恰好一台可管理服务器」，有两台就必然失败，只弹一个 2.6 秒的 toast，文案还错说「没有可管理的服务器」。
- 现在：可邀请线路 1 条 → 直接进入这条线路的邀请；2 条及以上 → 先进「选择线路」，选完再进。同一台服务器上的多条线路合成一个选项，不让用户做假选择。
- 没有可邀请线路时按钮**保留并禁用**，旁边 ⓘ 说明原因（以前是直接消失）。
- 三种拒绝分开说：没有记录 / 有多条线路请先选择 / 这台电脑只有使用权。

### 2. 四屏，一屏一件事（问题二、三）

- 选择线路 → 设置 → 已生成 → 已结束。**结果是状态，不是步骤**，所以没有步骤条；生成后表单整块消失，不再出现「表单下面长出一块结果」。
- 删除重复：有效期从 3 处降到 2 处（表单选一次、结果说一次），邀请码从 2 个控件降到 1 个（打码，点「显示」就地展开），18443 成功时不占位、失败时只一行；「设备名会自动记作…」整段删除。
- 「刷新状态 / 重新检查 / 重新开启接收服务 / 改用离线邀请」收进结果屏下方的折叠区，主路径只剩「复制邀请码」。
- 已生成时不再显示「生成邀请码」——它以前可以点，点下去必然报错。
- 结果屏一行说清：「线路名 · 10-24 20:34 失效（还剩 29 分钟）」，跨天时带日期。

### 3. 返回与完成分开（问题三）

- 「返回」只回退一步：设置屏回选择屏，选择屏回线路页。
- 「完成」表示离开但**不作废**；从「服务器与设备」进来的，完成回服务器页，不再一律扔回线路页。
- 「取消邀请码」移到左下并加了二次确认（作废这张邀请码？已经拿到它的电脑将无法加入），默认焦点在「返回」。
- Esc 永不作废邀请。

### 4. 离开页面不再锁死（问题四）

- 根因：离开页面时在途的管理操作没人收尾；完成回调又要求「邀请页正在显示」，两边互等，`PendingManagement` 永远清不掉，之后再进就是「邀请页暂时无法打开」。
- 现在收尾不再看当前在哪个页面（只看会话归属），渲染仍然只在服务器页或邀请页进行；迟到结果既不会丢，也不会把线路页换成服务器页。
- 生成完成后不再立刻自动查一次状态（这次查询本身就是触发窗口），首次轮询按 30 秒节奏走。
- 兜底：任何管理操作超过 90 秒没有结果，自动按「结果未知」收尾并提示去服务器页确认，不会再永久锁死。
- 再次进入同一张仍然有效的邀请，直接回到「已生成」，不再重建表单。

### 5. 顺手清掉的重复

- 「服务器与设备 → 设备与邀请」在网页版可用时只保留一个入口，卡片里那套完整旧表单不再重复渲染（降级壳仍保留）。

## 测试

- 网页回归 **634/634**（0.22.1 为 619，新增/改写邀请相关 15 组断言，含入口变异断言：把标题栏退回不带线路的写法后新断言必须变红）。
- `Test-WebInviteFlow` **95**、`Test-WebInviteSession` **84**（新增 3 轮「在途操作 + 离开页面」循环）、`Test-LineInviteMenu` **10**。

# TradeChannel 0.22.0-preview 邀请码有效期可到 24 小时，网页上也能生成邀请码

本版把「邀请其他电脑」做成网页原生页面，并统一了页面说明的呈现方式；线路卡的状态与操作按审查意见收口，术语统一为「日常上网 / AI 工具 / 交易软件」。

## 改了什么

### 邀请（A 组）

1. **邀请码的有效期不再固定 10 分钟**

   - 新增在线邀请有效期：10 分钟、30 分钟（默认）、2 小时、24 小时，另有自定义。自定义按分钟填 10–1440 的整数，或按小时填 1–24 的整数。
   - 服务器、部署宿主、加入端三处上限同步放宽到 86400 秒（24 小时）；加入端仍允许 5 分钟时钟偏差。
   - 选择超过 30 分钟时，页面直接显示：「超过 30 分钟的邀请码，新电脑需要 0.22.0 或更高版本；旧版本会提示有效期超过上限。」
   - 上次选择的有效期会被记住（纯界面状态，不进 `ui-preferences.json`）。

2. **网页上直接生成邀请码（新页面）**

   - 「邀请其他电脑」现在是网页里的独立页面，不再跳回 WPF 页面。三个入口：线路页标题栏（排「用邀请码加入」之前）、线路详情抽屉的维护组、服务器与设备页的邀请卡片。
   - 只有使用权的电脑（连接器模式、没有签名身份）看不到这三个入口。
   - 一台卡片走完整个流程：选服务器（单台只读、多台单选）→ 选有效期 → 生成 → 三段进度（每段超过 30 秒显示已用时间）→ 结果区（打码预览、复制、显示完整码、状态、到期倒计时、18443 结果、取消 / 再生成一个）。
   - 邀请码只在点「显示完整邀请码」时单独下发一次，不进任何状态快照；页面上平时只有 `TCI1.••••••••` 加末 4 位。
   - 状态轮询：进入时刷一次，倒计时归零再刷一次；页面可见且邀请有效时前 10 分钟每 30 秒、之后每 60 秒；连续 2 小时后停止，只留「刷新状态」；离开页面、窗口隐藏或最小化时停止。

3. **18443 可达性自检**

   只做 TCP 连接和 TLS 握手，用叶子证书的 SHA-256 与记录值比对；不发任何应用层数据、不带令牌。结果分六种：可连接、拒绝、超时、证书不匹配、TLS 失败、其他错误。生成邀请码时自动跑一次，也可以手动再测。结果只作建议：拒绝或超时仍会把邀请码给你，只有证书不匹配才提示重新生成。

4. **服务器上还有未到期的邀请码时的专门提示**

   邀请服务需要更新时，提示「服务器上还有未到期的邀请码，邀请服务需要更新。请先取消这些邀请码，或等它们过期后再生成。」，并提供「取消并重试」（用同一份输入重跑，幂等）。

5. **新电脑的名称不用再填**

   - 生成邀请码时不再要求输入「新电脑的名称」，系统自动记为「邀请 MM-dd HH:mm」；加入后可以改名。
   - 在线邀请、离线邀请、网页邀请三处用同一个标签，长度按最严的 64 字符截断。
   - 加入端仍然自己填设备名称，这一点没变。

6. **加入端的过期提示与有效期显示**

   - 「我有邀请码」的说明改为指向管理电脑「线路」页的「邀请其他电脑」。
   - 过期提示改为「邀请码已过期，请让管理电脑重新生成（可以设更长的有效期）。」
   - 有效期不是今天时，显示「MM-dd HH:mm」，不再只显示时分。

### 页面说明（B 组）

7. **长段落收进 ⓘ，标题旁就能看**

   凡是「为什么这样设计 / 有什么后果 / 两种选择的差别」这类解释，改成标题或字段旁的 ⓘ：鼠标停留 300 毫秒出现，键盘聚焦立即出现，点击可以钉住，Esc 或失焦关闭，同一时刻只有一个。说明文字只读，不能点、不能执行。

8. **维护页按用途分成三段**

9. **说明文字统一压短**

### 线路与术语（C 组）

10. **「上次连接正常」不再是「未测试」**

    只要这台电脑上一次用同一条线路、同一种连接方式成功连过，并且候选配置和清单都没有变化，卡片就显示「上次连接正常」和上次成功的时间，而不是「尚未测试」。换过连接方式、改过配置、或者换一条线路，都会退回「尚未测试」。检查失败仍然优先显示失败。

    - 标准连接 / 兼容连接改成单选：选中的那段亮，旁边标「默认」；自动选择时两段都不亮，旁边写「自动·标准」或「自动·兼容」。

    日常上网走交易线路时，AI 工具下拉框禁用，旁边直接写「日常上网走交易线路时，AI 工具也走交易线路。」

16. **启动失败留下故障代号**

    启动脚本崩溃时，状态里会记录一个故障代号（异常类型 @ 脚本名 : 行号），只保留字母数字和安全符号、最长 128 字符，不含任何消息正文。诊断报告和摘要里会显示「故障代号：…」，方便对照日志定位，同时不会把路径或凭据带出去。

### 名单页布局与批量勾选（D 组）

17. **行内按钮不再排成锯齿，中间也不再空一大块**

    根因在投影层，不在样式层：宿主用 `Grid @('*','Auto','Auto')` 表达「首列吃满、后两列按内容」，但投影只带列数、不带列宽语义，网页只能猜。0.20.10 曾用一行 CSS（`button:last-child{margin-left:auto}`）把症状按住，所以换个页面就复发。

    现在投影直读 `ColumnDefinitions`，把 `*` / `Auto` / 固定像素原样下发成 `data-colspec`；网页用真 CSS Grid 按同一份列宽排版，列坐标（`data-col` / `data-row` / `data-span`）也一并生效。未登记的形态不加这个属性，仍然走原来的 flex 路径，与今天完全一致。

    实测（1180 / 960 / 760 三档，chrome-headless-shell）：末列按钮右缘与网格右缘偏差 0px；跨行「移除」按钮左缘极差 0px；「移除」与「撤销移除」混排时右缘仍然齐平。

18. **状态胶囊、分段控件、步骤序号恢复原样**

    这三类以前都被当成普通卡片：状态胶囊被撑成一块砖（还叠了两层底色和 16px 内边距），分段控件的外框变成一张大卡片，步骤序号变成方块。

    现在宿主显式标注角色（`Tag.TCRole`：`chip` / `tile` / `group`）并带上原始边长，网页按角色排版。未标注的 `Border` 行为不变。

19. **图标恢复成线条图标**

    图标以前根本进不了网页：`Icon()` 画的是 `Viewbox → Canvas → Path`，`Path` 被投影丢弃，空的 `Border` 又被「无子节点即丢弃」的规则回收，于是图标位整块消失，行也跟着塌。

    现在宿主把图标名字过线，网页用同一份 24×24 路径几何还原，不另造图形。

20. **勾选改成「改完一次保存」**

    以前每点一个复选框就提交一次、重连一次，勾 12 个工具要等 12 轮。现在勾选、添加网址/程序、移除都先记在草稿里：

    - 页面底部出现一条常驻操作条：「已改 N 项，尚未生效」+「保存」+「放弃修改」。
    - 标题右侧的状态文字跟着变，从「名单当前跟随日常上网」变成「已改 3 项，尚未生效」。
    - 点「保存」才真正应用一次；成功后写「名单已保存：加入 X 项，移除 Y 项」。
    - 移除的自定义项先留在原地、文案改成「保存后移除」、按钮变「撤销移除」，不会点一下就从页面消失。
    - 有未保存改动时切页会被拦下来问「保存并离开 / 留在此页」，网页轨道和原生轨道都拦。
    - 保存失败分两种：完全没应用上写「没有保存成功，改动还在」；应用了但回读对不上写「已记录，这次没有应用成功」，并且不谎报成功 —— 判据是回读磁盘状态与勾选集合是否一致，不是「宿主说成功」。

    顺带把网页端的就地打补丁从「按位置配对」改成「按句柄配对」：以前中途插入一个按钮，会把后面的文本节点整体重建；现在只在句柄真的不存在时才新建节点。

# TradeChannel 0.21.8-preview 加入线路后再点「添加线路」，从第一步开始

## 修了什么

1. **加入一条线路之后，再点「＋ 添加线路」或「用邀请码加入」，一直回到上一次的结果页**

   现象：新电脑用邀请码加入成功后，点「＋ 添加线路」或「用邀请码加入」，都回到上一次的第 3 步「线路已加入」。第 1 步的两个选项进不去，所以既不能再加一条线路，也不能自己搭一台服务器。

   原因：加入结束后，程序内部的那次「加入会话」没有清掉。页面每 0.25 秒收到一份状态，里面一直带着这次已结束的加入，页面因此认为还有一次加入在进行，按第 3 步显示；页面自己设的第 1 步被覆盖。只有点页脚的「取消」「重置」，或者再校验一次邀请码，才会清掉。旧版表单同样：结束后保留「线路已加入」，再打开就停在结果页。

   修复（`ui/WebShell.ps1`、`web/app.js`、`ui/OnlinePairingPages.ps1`）：
   - 两个入口现在先让程序清掉已结束的加入会话，再打开添加线路页。清理不弹提示：线路已经加好，这里没有任何取消动作。
   - 加入还在进行时不清：保留进度，提示「上一条线路还在加入中，完成后可以继续添加」。这次加入的回调仍然有效，不会把正在加入的线路打断。
   - 页面在程序状态到达之前也不会闪一下旧结果。只忽略已经结束的会话，进行中的照常显示进度。
   - 从添加线路页离开（返回线路、侧栏任一页面、Esc）时，静默清掉已结束的会话，下次进来不会被旧结果占住。
   - 第 3 步成功后的按钮改为「去线路页 / 再添加一条线路」，页脚不再显示「取消」（放在成功之后像「撤销加入」）；「重置」在空闲和失败时改为「重新开始」，失败时保留「取消」。
   - 旧版表单：加入完成或已保存待检查后再打开，回到输入邀请码；「继续加入」仍然沿用原来的申请，不会在服务器上多登记一台设备。

六个契约版本号不变，服务器端不需要更新。改动只在本机的加入页，已加入的线路、连接与交易都不受影响。

   0.21.0 把「更多：连接方式与维护」当作重复入口删掉了，但真正重复的只有协议切换和测速。下面几项因此在 Web 界面里没有入口了，只能从 设置 → 操作记录 → 返回部署中心 绕进去：
   - 生成邀请码
   - 管理授权设备
   - 核对服务器身份
   - 本机连接网络

   现在线路详情抽屉的「维护」组新增两个按钮：
   - **「服务器与设备」**：直达这条线路的服务器与设备页。登录后可以生成邀请码、管理设备、核对身份，返回时回到线路列表。
   - **「连接方式与网络…」**：打开完整的连接方式页（默认协议、本机连接网络、网络回退）。这一页里也有「服务器与设备」入口。

   抽屉动作从 5 个变为 7 个，分组不变（主操作 / 维护 / 危险）。

2. **服务器身份变化的线路不再是死按钮**

   服务器重装导致公钥变化、记录已归档或对应多条记录时，线路会被标为暂不能连接。0.21.0/0.21.1 的问题有两处：
   - 卡片只有一个禁用的「需要处理」，首页主按钮是禁用的「连接」，用户看不到原因，也没有处理入口。
   - 其他页面仍可能对这条线路发出「连接」，宿主会直接丢弃，没有任何提示。

   现在：
   - 卡片状态写明原因，例如「关联服务器公钥与此线路不一致，请先核对服务器身份。」。
   - 卡片、抽屉、首页的主按钮都改为 **「核对服务器身份」**，直达这条线路的服务器与设备页。首页副标题改为「「线路名」需要先核对服务器身份」。
   - 旧页面、守护修复、推荐等路径仍对这类线路发出「连接」时，宿主不再静默丢弃，而是提示「这条线路的服务器身份需要先核对」，并打开同一页。

3. **邀请码加入统一到新流程**

   以下三处「用邀请码加入」会直接打开「添加线路」第 2 步（粘贴邀请码）：
   - 线路页标题栏
   - 没有线路时的空状态
   - 首页引导

   这和「＋ 添加线路 → 我有邀请码」是同一条流程。以前同一个按钮名对应两套实现：新用户点空状态的主按钮，会落到旧版表单。

   其他调整：
   - 「＋ 添加线路」仍然从第 1 步（选择方式）开始。
   - 旧版表单只保留页脚「遇到问题，用旧版表单」这一个出口。
   - 「这台电脑的名称」默认填本机名，和旧版表单一致。只填一次，用户清空后不会被回填。

# TradeChannel 0.21.1-preview 线路响应带减负

本版只改首页「线路响应」这一带的表达（`web/app.js` / `web/app.css`）与对应 UI 验收。宿主投影字段一个没加（仍只读消费 `Lines[].Quality30m` 的既有字段），连接事务、降级壳、六个契约版本号均未改动。

## 为什么改

0.21.0 的响应带把三件事挤在同一张卡里：

1. **逐条异常明细**（「21:12 尾延迟偏高：P50 205 ms / P95 636 ms」「21:08 这一次没有拿到读数」）——同一批异常在曲线上已经画过一次，文字清单又按时间戳列了一遍。
2. **六行统计口径**（「按 30 秒一次、最近 30 分钟统计；测量是交易出口的 HTTPS 往返（每次新建连接，含加密建连）……」）——一周看一次的解释，每天都占三行。
3. **琥珀色告警块**（未响应 1/60（1.7%）/ 其中超时 1 / 运行诊断）——把「一个数」讲成了「一个事件」，而这一屏已经有三处入口可以处理它。

三样加起来，卡里近一半面积在解释自己，读者要的三个数（多快、多差、丢了几次）反而要挑出来看。

## 改成什么样

版式按参考图重排：

- **标题行**只留「线路响应 + 线路名 + 语气标记」，「最近 30 分钟」靠右。
- **曲线**补纵轴刻度（0 / 中值 / 上限，上限按数据取整到 200 的倍数）、时间刻度（30 分钟前 / 15 分钟前 / 现在）与图例（P50 中位 / P95 尾延迟 / 异常采样），P50 下方铺 7% 强调色面积。
- **异常不再另起文字**：连续 3 桶（90 秒）没有回音才算断流，画一根竖虚线；尾部尖峰再加一个琥珀点。位置本身就是「什么时候」，逐条明细仍在「响应历史」里。
  - 单桶空档**不标**：30 秒一桶与探测节奏等宽，漏一次探测就会留一个空桶，而曲线本身会跨过去（`SPARK_BRIDGE`）。给它画竖线，等于曲线说「连着」、标记说「这里断了」，同一张图自相矛盾，也正好把用户要删掉的「某个时间点有没有拿到读数」又带回来。标记门槛与断线门槛同源，两个判断不会打架。
- **三格统计竖排**：典型响应 / 最慢响应 / 未响应，行间 hairline。未响应写成 `1/60 1.7%`，只有这一个数字变琥珀。
- **底部一行**：左边「测量口径 ＋」折叠块（默认收起），右边「响应历史 →」；有未响应时多一个「运行诊断」。

## 信息没有丢，只是换了位置

| 原来在哪 | 现在在哪 |
|---|---|
| 卡片底部的口径说明 | 「测量口径」折叠块，默认收起 |
| 「其中超时 N / 本机引擎未完成 N 次」 | 同一个折叠块内的第二行 |
| 两行带时间戳的异常明细 | 曲线上的竖虚线 + 点；逐条明细在「响应历史」 |
| 告警块里的未响应比例 | 第三格统计，数字变琥珀 |

## 尺寸

同一份快照、1240×900 视口下，这一带 319px → 294px（`reports/ui-response-band-0.21.1/shots/` 有对照截图）。高度只降了 25px，是因为曲线从 96px 长到 132px 换来了刻度和图例；变少的是文字，不是证据。

## 兼容性

- `Lines[].Quality30m` 零改动。旧投影（只有 `Samples`）仍走单线曲线，不出坐标轴与图例，也不伪造异常标记。

- W1-07 异常断言从「文字清单 2 条」改为「图上标记」，并新增「单桶空档不标异常」「连续 3 桶断流合并成一根标记」「断流标记不带点」「不再印时间戳式异常行」。

# TradeChannel 0.20.11-preview 修掉「永远连不上」的连接死锁

本版只改「上次连接没收尾时，这次连接怎么放行」，不改连接事务的判定标准、不改线路协议、不改六个契约版本号。

## 死锁是怎么来的

现场：点「连接」→ 提示需要核对 → 点「检查上次连接」→ 提示「故障记录已处理」→ 再点连接 → 又回到需要核对。循环，永远连不上。

- 升级时线路仍在后台跑，引擎异常结束，supervisor 收尾时「恢复代理设置」抛错，`runtime.json` 落盘 `State=StoppedWithError` + `CleanupError=true`。
- `Observe` 把「已停止 + 清理未完成」判成 `Unknown`，而所有连接路径都要求 `Running`/`Stopped`——于是连接被拒。
- `CleanupError` 只有「新建会话」才会重置，而新建会话正是被它挡住的。**唯一的解药被病因锁在门里。**
- 「故障记录已处理」是空集误判：没有任何待处理事务时，`Resolved` 也算 `true`。

## 改了什么

1. **停止状态不再被清理标记一票否决**（`RuntimeBridge.psm1`）。会话在不在跑，由活进程清单独立证明；清理没写完是另一件事，改为独立字段 `CleanupPending` 上报，不再污染状态枚举。
2. **连接闸门先收尾再放行**（`ConnectionTransactions.psm1`、新增 `runtime/TradeChannel.SessionCleanup.ps1`）。遇到 `CleanupPending` 时先跑一次幂等收尾：核验记录归属已结束 → 重放代理日志 → 归一化账本，收尾成功才放行；代理值与记录冲突时要求用户选择，不覆盖；无法核验时保持原拒绝。
3. **空集不再算「已处理」**（`Worker.ps1`）。零条记录时返回「没有待处理的故障记录」，并附带 `Reviewed` / `Pending` 两个计数，界面能分清「真的处理了」和「本来就没有」。
4. **清理失败可定位**（`runtime/Run-TradeChannel.ps1`）。收尾异常的 catch 追加异常类型名（只记类型，不记原文，避免配置内容进状态文件）。
5. **维护与恢复新增入口**（`ui/WebTools.ps1`）。「上次连接的清理」一行，可按需手动完成，与连接时自动收尾走同一个函数。

## 兼容性

`ManagementApi` / `Pairing` / `LineProfile` / `ConnectionBundle` / `ProtocolSelection` / `DualDeployment` 六个版本号不变；`runtime.json` 只新增 `CleanupResolvedAt` / `CleanupResolution` 两个可选字段，旧版本读到会忽略；运行事件新增 `CleanupResolved` 类型，旧记录照常显示。

## 升级注意

新增 `runtime/TradeChannel.SessionCleanup.ps1`，打包白名单（`deployment/BuildPreviewCore.ps1`）与启动必需项（`Startup.psm1`）本版都已补上，发布包清单条目数随之变化。升级后登录启动任务需要重新注册。

# TradeChannel 0.20.8-preview 线路响应改看 P50/P95，异常单独列出来

本版只改「线路响应怎么画、异常怎么呈现」，不改采样节奏、不改连接事务、不改六个契约版本号（ManagementApi / Pairing / LineProfile / ConnectionBundle / ProtocolSelection / DualDeployment）。0.20.7 的隐藏态降频与读进程复用一并包含在本版内。

## 为什么改

原来的曲线是「每 30 秒一个桶的平均值」。平均值有个毛病：一次超时就能把整段拉高，看不出到底是**普遍变慢**还是**偶发尖峰**——而这两种情况对交易的含义完全不同。现在改成两条线：

- **P50（实线）**：这段时间里"平时多快"。
- **P95（虚线）**：这段时间里"最差的那 5%"。

两条线分开，普遍变慢会抬 P50，偶发尖峰只抬 P95。

## 异常单独列出来

图下面新增一个异常列表，只列两类真正需要知道的事：

- **这一次没有拿到读数**（整桶未响应）
- **尾延迟偏高**：P95 达到 P50 的 3 倍以上

最多列最近 4 条，带时间。其余波动交给两条线自己表达，不再堆文字。

## 数据怎么来的

- `LineQuality.psm1` 的统计对象新增 `MedianLatencyMs`，与原有的 `P95LatencyMs` 并列；分桶一并带出 P50/P95。
- 投影层 `GetTCWebQuality30m` 新增 `MedianSamples` / `P95Samples` 两条逐桶序列，以及窗口级的 `MedianLatencyMs` / `P95LatencyMs`。
- 历史窗口（线路详情里的日/30 分钟）的桶也透传 P50/P95 与样本数，为后续在同一张图上加区间做准备。

## 兼容性

宿主没有下发 P50/P95 序列时（旧数据、或只有平均值的窗口），图表**自动退回原来那条单线**，不会白屏、也不会凭空生成异常事件。这一点由断言 `W1-07-06 / W1-07-07` 钉住。

## 顺手验收的一件事（不改代码）

「退出界面（连接保持）」这条路径做了实测：点 X 后界面进程 **227 ms** 退出，WebView2 子树 **438 ms** 全部清空，守护进程与 sing-box 保持运行，连接未中断。距离 5 秒的验收线还有很大余量，因此**没有改退出逻辑**。

## 明确没做的事

- **采样节奏没动**：仍是可见 30 s、隐藏 60 s。断线判定来自监督进程的运行状态，与质量采样无关，但托盘劣化提醒依赖采样，降频前必须先实测提醒延迟。

- **没有把状态改成管道推送**：那会动到 PageGeneration 防串页机制。
- **没有扩展读进程白名单**：实测 110 秒内 fork 次数为 0，周期性读动作已经全部走常驻读进程，再并入只是让常驻进程多背模块。

# TradeChannel 0.20.7-preview 后台不再空转：隐藏时停止刷新、读请求不再 fork

本版只改「界面刷新与读请求的调度方式」，不改任何功能语义：数据、连接事务、线路协议、配对、部署流程与六个契约版本号（ManagementApi / Pairing / LineProfile / ConnectionBundle / ProtocolSelection / DualDeployment）全部未变。0.20.6 的窄窗口与面板同源改动一并包含在本版内。

## 隐藏态不再刷新快照

- 以前：250 ms 的界面定时器**无条件**调用 `SyncTCWebState`，窗口在托盘里、甚至最小化时仍在重建整份快照并推给 WebView2。
- 现在：只有窗口可见且未最小化才走快照，且降到每 2 个 tick（500 ms）刷一次；状态变化仍由各处的 `SyncTCWebState -Force` 立即推送，不受降频影响。
- 隐藏时计数清零，**恢复可见后的第一个 tick 就重建**，不会出现「点开托盘还看到旧数据」的半秒窗口。
- 托盘气泡提醒依赖的 `UpdateTCLineQuality` **没有被包进这个判断**，隐藏态照常运行——这是本版最需要守住的一条不变量，已由 `tests/Test-PerfGuards.ps1` 钉住。

- `GetTCWebSnapshot` 每次都会重建文案目录（`Get-TCTextCatalog`）和连接方式投影，这两份内容在运行期不变。
- 现在首次快照时建一次并缓存，之后直接复用；缓存随界面重置一起清空。

## 质量与待机采样按可见性分档

- 线路响应采样：可见 30 s、隐藏 60 s；待机质量采样：可见 60 s、隐藏 120 s。
- 理由：隐藏态本来就没有人在看曲线，把采样频率减半直接省掉一半的探测与写盘；可见态口径不变。

## 读请求不再为三个动作各起一个进程

- `LineQuality`、`StandbyQuality`、`Nodes` 三个只读动作并入常驻读 worker，不再每次 fork 一个新的 `powershell.exe`——每次 fork 的冷启动成本与内存抖动都落在读请求的响应时间上。

- 配套修了一个集成契约：读会话侧（`Worker.ps1`）有**自己的一份**允许动作白名单，与 `WorkerContracts.psm1` 的 `ReuseReadProcess` 是两份清单。只改前者时，`Nodes` 会被路由到共享读进程后以 `ReadActionNotAllowed` 直接失败——本版把两份同步，并加了断言防止再漂移。

- 原因：副行的「其它」是残差项（总数减去超时数），超时为 0 时它必然等于总数，写出来就是复述。
- 现在只有存在两种以上原因时才列分解（如「其中超时 1 · 其它未响应 2」）；单一原因时副行留空，主行已经把次数说完。

## 一个动作只有一个名字

- 打开诊断报告的按钮原有三个名字：「查看诊断」「运行诊断」「检查保护」。现在 12 个按钮统一为**运行诊断**。
- 「检查保护」被取消：它打开的是完整诊断报告，名字只承诺了其中一节；而且它旁边就是「修复保护」（实际动作是重新连接），两个词形近义反，容易被当成一对。
- 「重新检查」统一为**刷新**：三个入口发的是同一条 `refresh`，却有两种叫法。首页数据过期时，提示条不再重复渲染刷新按钮（状态卡里已经有一个），其他页面保留。

## 两种「读不到」分开说

- 以前：数据过期时标题写「状态未知」、提示条也写「状态未知（已 N 秒未更新）」，同一句话在 60px 内出现两次；而真正读不到状态时反而写「状态暂未更新」——「暂」字还暗示它会自己好。
- 现在三处各说一件事：标题**状态未知**（连接状态确实不知道）、副标题**连接状态可能已变化。**、提示条**数据过期（已 N 秒未更新）**（原因＋证据＋刷新入口）。
- 真读不到时用**无法读取**（原「状态暂未更新」），四个字，不承诺会自动恢复。
- 保护状态同样收成三个词：**交易保护已开启 / 交易保护未完整开启 / 交易保护状态无法确认**。原来同一状态在卡片叫「需要处理」、在横幅叫「未完整开启」。

## 设置页那个假开关

- 「线路变差提醒」右侧原本是一枚写着「已开启」的徽章，看着像开关但点不动，而同页其他行都是真开关。
- 现在改为纯说明：「始终开启，不可关闭」。做成真开关需要宿主侧字段，本版不做。

## 验收门禁补了一个洞

- 原来「已连接时当前响应只出现一次」这条断言只数带 `data-testid` 的节点，而线路卡那处没有 testid——所以重复一直都在，断言一直是绿的。
- 现在改为按作用域判断：状态卡里恰好一个、使用中线路卡里既没有「当前响应」字样也没有数字格，且仍有 10 分钟曲线。这两条断言不依赖 testid，改名字或搬进公共函数都不会让它们失效。

## 已知局限（本版接受）

- **只统一了 web 前端**。原生窗口（非 WebView2）对同一状态仍写「状态暂不可核验」，本版未改，也不宣称"全站统一"。
- **390px 下首页整体过挤（本版未修，0.20.4 同样存在）**：侧栏固定 140px，正文只剩 250px；状态卡标题「已连接」折成两行，主按钮「断开连接」右边缘超出卡片 28.8px（也超出 390 视口 4.8px），「标准连接」折两行。这是响应式断点问题，与本轮的重复表达无关，单独一版处理。
- 侧栏迷你状态在首页仍会显示一次响应值：它是给「状态卡不在视口内」的其他页面用的，本版保留。
- 首页「应用走向」里的交易软件名与状态卡副标题仍是同一个字符串（已连接时）。两者主体不同（路由表 vs 状态），本版未合并。
- 线路详情抽屉里的「未测得」未并入「未响应」：两个数分母不同（一个含引擎未完成、一个已剔除），合并会让一个词对应两个数。

# TradeChannel 0.20.4-preview 响应曲线不再被单个空桶打断

本版只修首页「线路响应」的曲线绘制。数据、宿主、统计口径与契约版本号全部未变；0.20.3 的面板改动一并包含在本版内。

## 修正：健康线路上曲线断成一截一截

- 现象：未响应为 0、全部探测都成功，曲线却断成七八段，看起来像线路反复掉线。
- 原因不是丢数据。30 秒一个桶，探测也是 30 秒一次，两者宽度相同；探测偶尔跳过一拍（实际记录里 440 次采样中有 50 次间隔是 60 秒），那个桶就没有读数。界面原来遇到空桶就断线，于是每个空桶在图上凿一个洞。
- 实测这个窗口：60 个桶里 51 个有读数、9 个空桶，且空桶连续长度只有 1 和 2，从未出现 3。也就是说这些洞全部是节奏抖动，不是线路问题。
- 现在只有**连续 3 个空桶（90 秒没有任何读数）**才断线；1–2 个空桶由曲线直接跨过去。真正的断流（引擎停了、断开过）仍然会断开，图上依然看得见。
- 无障碍标签同步改为「超过 1 分钟无读数的区间不连线」，不再说「缺失区间不连线」——那个说法会让读屏用户以为有空桶就是缺数据。

## 已知局限（本版接受）

- 跨过 1–2 个空桶的区间是直线插值，图上无法区分「平滑」和「没有读数」。判断有没有未响应看下面那一行，不要看曲线形状。
- 桶边界按查询时刻滚动，刷新时同一批采样可能落进相邻的桶，空桶位置会轻微移动；这不影响读数，也不影响统计。

# TradeChannel 0.20.3-preview 首页响应区去重与面板归属修正

本版改首页「线路响应」区的呈现口径与数据归属，宿主只修一处告警归因。连接事务、线路协议、配对、部署流程与六个契约版本号全部未变。

## 修正：面板可能显示另一条线路的统计

- 「线路响应」原来取「首页默认线路」，状态卡的「当前响应」取实际连接的线路。两者可以不是同一条：连着 A、首页默认 B 时，同一屏上半部是 B 的实时响应，下半部是 A 的 30 分钟统计，而面板标题只写「线路响应」。
- 现在连接中（且交易出口为自建线路）取实际连接的线路，其余情况取首页默认线路。
- 面板标题常驻线路名；断开但窗口内仍有历史时加「· 上次连接」，避免「已断开却显示 287 ms」被读成实时。
- 宿主侧同步修正：投影改为按**实际连接的连接方式**取序列。原来按「已保存偏好」取，偏好为「自动」时匹配不到，会退到第一条序列——同一线路名下可能展示另一套传输（UDP/TCP）的曲线。只修界面不修这里，等于给错数据加了标签。

## 修正：删掉与「未响应」重复的两个计数

- 去掉「成功次数」「采样次数」两格。宿主定义 `未响应 = 采样次数 − 实测数`，三个数只有两个自由度；「成功次数」还会被读成「成功连上了 N 次」，且保证不了质量（一次 6900 ms 的探测同样算成功）。
- 原始计数仍在「响应历史」抽屉里（`N 次成功 · M 次未测得`）。
- 「相邻采样平均变化」移出首页：它没有阈值，任何取值都不改变决策，却与「中位」同单位并排，容易被读成「287 ± 410」。首页改为「最慢响应」——同一单位、同一个轴，回答「最坏会坏到什么程度」。
- 「中位」改称「典型响应」，统计口径（标准中位）未变。

## 修正：零失败不再说「无失败」，也不再催你诊断

- 健康时副行留空。「无失败」与主行的 `0/55（0%）` 同义，而且它把「这次探测拿到了读数」升级成「线路没问题」。
- 「运行诊断」原来只要副行非空就出现，而「无失败」也是非空——最健康的窗口反而有诊断按钮。现在只在真有未响应或本机引擎故障时出现。

## 修正：同一故障，面板与告警不再给出相反结论

- 质量告警把「本机引擎没跑起来」算成坏样本，连续 3 次会打出「交易出口连续 3 次无法取得延迟」，而面板同时写「未响应 0/55」。现在引擎故障既不计入坏样本，也不清零已有的坏样本计数（清零会让一次引擎抖动解除一个真实的线路告警）。

## 界面细节

- 面板数字格由固定 2×2 改为按数量自适应，删格后不留空位。
- 有未响应时状态条变成整条 warn 色块。放大的是这一条，不是度量格——出问题的时候不该把证据变小。
- 线路卡缩略图改为近 10 分钟（面板仍是 30 分钟），同一屏不再画两遍同一条曲线；无障碍标签同步改为 10 分钟。
- 断开态首页不再同时出现两个「响应历史」入口。
- 脚注由两段约 200 字合并为一句，写清测量机制（每次新建连接、含加密建连）。

## 已知局限（本版接受）

- 刚切换到新线路时面板会显示「暂无读数」，要等新线路积累样本；原来看起来「有数据」的那些，其实是另一条线路的。
- 「最慢响应」会被单个尖峰主导，这是有意的：对交易用户，误报在安全侧好于漏报。
- 验收测试同步改写（新增 `quality-worst`，删除 `quality-samples`/`quality-total`/`quality-change` 的断言）。

# TradeChannel 0.20.2-preview 线路响应的「未响应比例」

本版只改首页「线路响应」区底部的两行文字与样式。宿主逻辑零改动，只补了一条契约注释；投影键集合仍是 7 键，连接事务、配对、部署流程与六个契约版本号全部未变。

## 新增：未响应比例

响应区底部原来有两行独立输出——「3 次未测得」和「其中 3 次超时」——讲的是同一件事。本版合并成一行，并补上比例：

- 正常时显示 `未响应 3/25（12%）`，副行只列非零的拆分：`其中超时 3`；超时以外的原因（连接失败、读数无效、出口未返回延迟）归到 `其它未响应 N`，不会出现「未响应 2/30 · 其中超时 0」这种自相矛盾的副行。
- 分母是**有效尝试数**：`采样次数 − 本机引擎未完成次数`。本机引擎自己没跑起来不是线路问题，把它算进分母会把引擎故障摊薄成线路失败——引擎挂 10 次、线路失败 3 次会显示 12%，而真实的线路失败率是 30%。
- 分子同理剔除本机故障，其余四种原因（超时、连接失败、读数无效、出口未返回延迟）都算「这次没拿到可用数值」。
- 有效尝试不足 10 次时只显示 `未响应 1/3（样本不足，暂不显示比例）`：3 次里失败 1 次是 33%，会让人以为线路崩了。
- 比例小于 10% 保留一位小数（`1/60` 显示 `1.7%`，写成 `2%` 会差 20%），10% 及以上取整。
- 本机引擎一次都没跑起来（有效尝试为 0）时主指标显示 `—`，副行写明 `本机引擎未完成 5 次，未计入线路判断`——不允许静默。窗口内一次采样都没有时主指标同样是 `—`，副行留空，不写「本机引擎未完成 0 次」这种报告一件没发生的事的句子。
- 比例永远不超过 100%：宿主按 `未响应 = 采样次数 − 实测数` 计算，正常不会越界；万一投影写坏，也会夹到 `10/10（100%）` 而不是把 `150%` 送到屏幕上。
- 全部正常时显示 `未响应 0/10（0%）`，副行 `无失败`。
- 响应持续异常时，副行右侧给出「运行诊断」入口，不在主行后面写任何「建议换线」类的话。

脚注同步说明口径：未响应＝这次探测没拿到可用数值（含超时、连接失败、出口未返回延迟）；本机引擎自身故障已剔除，不计入线路判断；本窗口内 0 次不代表链路没有丢失。

## 术语：为什么叫「未响应」而不是「丢包率」

- **仍然没有丢包率。** 宿主的质量统计里 `PacketLossPercent` 恒为空、`PacketLossMeasured` 恒为假；测量本身是交易出口的 HTTPS 往返，不是 ICMP/UDP 包序列。请求层没拿到数不等于包丢了，所以名字刻意不叫丢包率——否则用户会按网络问题处理。
- **`%` 不再一律禁用，但只允许 `N/M（x%）` 结构。** 原来禁用 `%` 的本意是禁止「没有分母的百分比」（`0.0%` 这类凭空结论），不是禁止一切比例。有分母、有窗口、有样本量门槛的比例是可核验的，所以放开；静态扫描同步从「禁止 `%`」改为「每个 `%` 附近必须有 `/数字`」。`丢包`、`丢包率`、`抖动`、`健康度`、`128 次采样` 仍然禁用。
- 0.20.1 章节里的「N 次未测得」表述已由本版的未响应比例取代，历史章节保留原样。

## 已知局限（本版接受）

- 30 分钟窗口可能跨两次连接，比例是「最近 30 分钟」而不是「本次连接」。界面文案只说最近 30 分钟，不说本次连接。
- 比例只出现在线路响应区。线路卡、状态卡、抽屉都不加这个数，避免同屏重复。

# TradeChannel 0.20.1-preview 首页状态高亮修正与线路响应

本版只改首页与线路页的呈现，连接事务、线路协议、部署流程、持久化格式与六个契约版本号全部未变。

## 修正：同一屏上互相矛盾的高亮

- **非当前线路不再显示「切换已完成」。** 之前只要那条线路自己不是当前线路，就会把历史结果条原样画出来：用户连着 A 线路，B 线路下面却写着「切换已完成，实际出口验证通过」。现在只要有任何线路处于已连接状态，所有线路卡都不再渲染「已完成」结果条——当前状态只由状态卡和「使用中」徽章表达；断开之后，这条结果才作为历史证据重新出现。
- **历史结果条改过去时。** 已经回到切换前、没有开始、通道已停止、结果需要核对这四种终态，只要当前有线路在连接中（包括它自己），标题前就加「上次切换：」，整条降为中性灰底，不再和「使用中」徽章抢当前状态——一条线路不可能同时「使用中」和「已回到切换前的状态」。宿主给的原句一字未改；断开后照旧按现在时显示。
- **「交易出口」徽章不再被拉满整行。** 事实卡是纵向弹性容器，徽章被默认拉伸成一条横贯卡片的色块；现在徽章只包住自己的文字。
- **保护告警与保护事实卡不再同屏重复。** 首页已经有保护事实卡时，顶部不再重复一条同样的黄色告警；其它页面照旧。

## 新增：线路响应区

首页在状态卡之下新增独立的「线路响应」区：左侧是近 30 分钟曲线，右侧四项数字——中位、相邻采样平均变化、成功次数、采样次数，下面是未测得次数与「其中超时 / 引擎未响应」的拆分，以及一行口径说明。断连但仍有历史数据时照常显示。

状态卡同时做了减法：只保留结论、当前线路、引擎运行时长、连接方式和主按钮，不再重复一遍响应数值与曲线。

## 关于「丢包率」与「128 次采样」

- **丢包率不会出现。** 宿主的质量统计里 `PacketLossPercent` 恒为空、`PacketLossMeasured` 恒为假——这个产品没有丢包测量能力。写 0.0% 等于凭空造一个数。
- **采样次数上限是 60。** 30 分钟窗口按 30 秒一个桶，最多 60 个桶；早期原型里写死的「128 次采样」在 30 分钟窗口内不可能出现。本版显示的是真实的采样次数。
- **「抖动」改叫「相邻采样平均变化」。** 测量对象是交易出口的 HTTPS 往返（含 TLS 建连），叫抖动会让用户以为是网络抖动。

## 0.16.7 已有行为：多轮检测证据修复

- 修复汇总比较编号与最后一轮探针凭据编号混用，导致真实 TCP 成功结果被误报为 `ConfigurationChanged` 的问题。
- 每轮探针分别核对正式配置和清单哈希、临时配置哈希、探针编号及网卡绑定；比较编号、协议顺序、缺失轮次与重复回执也需一致。
- 更新比较回归用例，覆盖真实探针使用的派生凭据格式，以及任意一轮被改动时拒绝推荐的情况。单次探针、旧格式证据、真实超时和可选网站验证保留各自含义。
- 包含 0.16.6 的管理初始化中断续接修复。沿用既有 Linux 网络资源，不增加网络调参或自动启用线路。

## 0.16.6 管理初始化中断续接

- 增加只读 `management_recovery_state`。服务器在共享锁内核对原计划摘要、目标身份、配置修订号、计划过期和管理文件缺失；未过期、部分初始化、配置变化或未决事务均不能解除恢复。
- 原计划未生效的核对还验证原设备授权、UDP 健康和最终服务器状态。结果保存为 `NotApplied`，原意图、原计划及证明进入历史记录；不会将旧操作标为执行成功。
- 核对通过后停在继续检查点，撤销旧计划的批准。新计划经过原有预览和批准入口执行，原设备及隧道密钥保持。
- 界面区分已生效和未生效的核对结果；两种结果均绑定原操作后解除相应等待记录，其他事务和本机探针清理继续保留。

此版本保持 0.16.5 的 Linux 网络资源格式，不增加网络调参或自动切换线路。源码测试、完整包和原中断服务器的现场结果分别记录在交付报告中。

## 0.16.5 已有行为

0.16.5 修复部署恢复与向导隔离问题：

- `apply`、`authorize`、`management_apply`、`transport_apply` 分别核对原变更意图、已认证会话、计划、设备和服务器状态。公钥存在或 UDP 正常不再单独视为变更完成。
- 管理初始化核对检查未决事务、配置健康、完整公钥字段和修订号；始终更新已认证服务器台账及运行快照。TCP 核对还检查生效计划、配置修订号、原设备参数和最后一次服务器状态。
- 增加只读“核对服务器状态”入口。每次核对最多读取 5 个结果，期限 3 分钟；证据不足停在具体问题，不自动循环。核对成功停在可继续检查点，保留其他恢复事项。
- 新建与恢复使用独立向导实例，异步结果绑定原运行和会话；前置参数错误在派发前拒绝，避免误报结果未知。未决操作按已核实的服务器范围限制冲突任务。
- 登录问题、恢复动作和技术详情提供明确入口，部署表单的主操作固定在可见底部。
- 保留已发布的网络资源格式，修复旧部署被实验性资源生成器误判为漂移的问题。未完成回退与实测的 BBR、缓冲及 ICMP 修改未纳入本版。

本版验证范围见交付报告。程序升级、原中断服务器的实际恢复及生产连接验收分别记录；安装程序继续要求旧程序和网络引擎退出。

## 0.16.4 已有行为

0.16.4 基于 0.16.3。连接、配置补全、后台等待和恢复入口共同使用明确的原线路与连接方式；保留交易软件运行保护、身份与哈希核对，以及切换失败后的原连接恢复核验。

- 已保存的有效 UDP/TCP 选择，不再因缺自动推荐证据、可选网站验证或未使用的备用协议失败而被一并禁用。真实身份冲突、配置损坏和未清理任务仍需处理。
- 修复相同连接选择在预览与提交之间被误判为已改变、要求重复预览的问题；真正改变线路、配置或分流选择时仍需重新预览。
- 缺默认时选择已有连接方式；缺配置时定位原准备步骤；旧固定地址或网卡改名时提供本机网络更新预览，完成后回到原连接预览。
- 重试检查使用独立临时探针，不替换正式配置或清除默认选择。网络策略更新生成新版本，保留原版本和配套默认绑定，并提供回退入口。不会在后台批量迁移线路。
- 监督进程区分网卡正常、确定缺失和读取不确定。短暂读取异常使用独立接口证据复核；持续无法核验时保留交易保护并受控停止。
- 后台读取有期限，用户请求可排队；变更结果未知时保留原请求和核对入口，不自动重复执行。界面刷新保留编辑、选择和密码控件。
- 正常状态读取使用随包编译组件、按需模块与复用快照。服务商缓存仅包含展示摘要，配置变化后失效；实际连接和修改重新核验原始数据。
- 打开中断部署只查看；空闲离开关闭管理会话，进行中可返回列表或请求当前步骤完成后暂停。新凭据优先及有界重连保持。
- 系统代理修改先保存持久恢复记录。会话结束后按当前值核对恢复；用户后来修改的设置进入选择入口，不直接覆盖。
- 包安装器验证文件、版本、专用目录和权限，并保留程序回退备份。状态记录采用无损紧凑写入；接近 4 MB 上限会在运行报告提示。
