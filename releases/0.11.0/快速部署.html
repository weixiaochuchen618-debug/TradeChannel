TradeChannel 0.9.2 · 预览版

先连通道，再打开交易软件

概览页负责连接和三条流量线（交易 / 日常上网 / AI 助手）；线路页管理自建线路、AI 助手名单、BatVPN 与交易名单；部署页准备新电脑和服务器；设置页管理登录与维护。

日常使用交易电脑转发服务器更换与迁移完整指南

每天怎么操作

桌面没有入口时，双击解压目录内的 创建桌面入口.cmd，或在「设置」点击「创建桌面快捷方式」。之后使用桌面 TradeChannel 图标；请保留完整解压目录。

  1. 打开 TradeChannel.exe，允许管理权限。打开界面只读取连接状态。
  2. 需要日常上网走 BatVPN 时，先打开 BatVPN 连接节点，保持白名单模式（不要用 VPN 模式）。
  3. 点主按钮连接。在「流量走向」中：交易选自建线路；日常上网选本地直连、BatVPN 或走交易线路；AI 助手选跟随日常上网或走交易线路。日常上网和 AI 助手点击即生效；切换交易线路会先确认。
  4. 在「出口检查」查看交易出口和日常出口，再打开 NinjaTrader / TradingView 分别核对登录、实时行情和历史图表。

「设置 → 登录 Windows 后打开控制台」默认关闭。可选开启只打开界面，不自动连接。退出本方案才使用「维护与恢复 → 解除 NinjaTrader 保护」；日常断开不需要解除。
香港故障，切到 BatVPN
  1. 先在 BatVPN 连接节点，将其内部模式改为全局。
  2. 概览页「交易」选 BatVPN 备用，确认切换。
  3. 检查出口，在交易软件里重新连接并核对账户状态。香港恢复后切回自建线路，BatVPN 改回白名单。

当前是手动切换，没有自动故障转移。服务商须先在本机节点配置中加入；历史行情稳定性需单独验证。

AI 助手单独走交易线路
  1. 在「线路 → AI 助手名单」打开需要的助手：Mirasim、Claude Code 与 Claude 桌面版、Codex、Google Antigravity（反重力）、CC Switch（接口中转）、Claude / ChatGPT / Gemini 网页版；也可添加网址或程序。Mirasim 的助手由 Claude Code 执行，两项都要打开；Codex 或 Claude Code 经 CC Switch 本地代理联网时，还要打开 CC Switch。
  2. 概览页「AI 助手」选走交易线路，立即生效，不中断交易连接；其他应用仍按「日常上网」出网。
  3. 桌面程序按程序识别；网页版只匹配浏览器访问所列网址。名单网址经交易线路解析 DNS；助手访问名单以外、在本地被屏蔽的网站可能失败，可把网址加入名单。
升级旧线路配置

从 0.4 / 0.5 升级后，概览页会提示「线路配置可以升级」。退出整个 NinjaTrader 后点「升级」，约 15 秒完成并重新连接；原配置保留用于回退。升级后才能使用 AI 助手名单、让日常上网走 BatVPN；之后切换都不需要重新连接。

状态说明

「已连接」说明本机进程和控制接口正常，不代表所有交易服务都正常。日常上网选 BatVPN 但它暂不可用时会显示「暂时直连」及原因，恢复后自动切回。「正在连接／断开」会禁止重复操作；遇到「连接需要处理」按页面提示重新检查或断开。重启后不会把旧文件里的 Running 当成仍已连接。

配置交易电脑

已有可用通道
  1. 完整解压安装包，运行 TradeChannel.exe。
  2. 「线路 → 登记当前通道」，只登记，不切换网络。
  3. 回「概览」核对三条流量线和状态；旧配置会提示升级。
新电脑已有 .conf / .zip
  1. 部署向导选「配置交易电脑」，查看环境检查。
  2. 使用 WireGuard 客户端 .conf，或在旧 WireGuard 左下角导出所有隧道为 zip。
  3. 给节点命名、选文件，检查 NinjaTrader 路径与本地 DNS。BatVPN 备用是可选项。
  4. 保存并校验线路，此时不切换网络。
  5. 在线路页点「设为交易线路」。退出整个 NinjaTrader 后，在概览页连接或确认切换。
  6. 检查出口、登录、实时行情、历史数据和 TradingView。工具不会自动下单。
新电脑没有配置：申请授权
  1. 部署向导 → 申请或完成设备授权 → 生成设备申请，选一个新空目录。
  2. 只把 public.request.json 复制给服务器，私钥留在本机。
  3. 服务器从同页面进入「服务器授权入口」，添加设备并返回授权文件。
  4. 回本机选择原申请目录、授权文件，合成客户端配置，再导入节点。
仍然使用 WireGuard 协议。交易电脑通过内置引擎连接，无需操作旧 WireGuard GUI；自建服务器仍需要 WireGuard 服务。旧客户端可保留作回退，旧隧道不能同时激活。

配置转发服务器

低配 Linux VPS：从本机部署
  1. 在本机打开「部署 → 部署 Linux 服务器」。填写公网 IPv4、SSH 端口和用户名；适配目标为 Ubuntu 24.04 / Debian 13 x86_64 专用虚拟机。
  2. 点击只读检查，在独立登录窗口核对主机指纹并输入密码或密钥口令；密码不在聊天或任务文件中填写。
  3. 环境通过后生成计划，按提示在云安全组放行 WireGuard UDP 端口，保留 SSH。
  4. 审阅目标后部署，完成后生成本机客户端资料并导入新节点。当前香港通道保持，真正切换需要另行操作。
  5. 先验证外网、行情、重启和恢复，再停用旧服务器。详细步骤见 Linux 部署指南。
新建专用转发节点
  1. 通过远程桌面登录目标服务器，保留厂商控制台恢复方式。
  2. 复制完整包，运行同一软件，部署向导选择「配置转发服务器」。
  3. 检查系统和已有资源。未安装 WireGuard 时，可选择「使用随包安装程序」或「从官网下载并安装」，均校验官方签名。随包 EXE 是联网安装引导器，两种方式都需要访问 WireGuard 下载站。
  4. 填写节点名称、公网 IPv4:UDP端口、外网网卡和未冲突的隧道网段。
  5. 生成变更计划。在云平台为该服务器放行对应 UDP 入站端口，保留远程桌面规则。
  6. 审阅节点、NAT 和端口后，应用服务器计划。
  7. 接收交易电脑的公开设备申请，分配独立地址，将授权文件复制回交易电脑。
  8. 客户端完成连接和真实公网转发检查后，才算整条线路验收完成。
服务器已经有 WireGuard / NAT

保留原部署。新建向导发现资源或网段冲突会停止，不自动覆盖已有 Peer。现有服务器可继续提供对应客户端配置供本机导入。

换节点、换电脑

香港节点换成美国节点

保留香港 → 在美国服务器新建节点 → 授权当前电脑 → 本机添加独立客户端配置 → 线路页「设为交易线路」→ 概览页确认并验证。需要新服务器的公钥、地址与授权，不是只改旧 IP。

换电脑 / 两台电脑同时使用

「部署向导 → 换电脑 / 迁移设置」：旧电脑导出设置，新电脑导入后重新授权。设置包不含私钥，不等于完整身份备份。每台同时在线的电脑必须使用独立身份；保留已有受限备份。

部署失败怎么办

旧节点和部署备份保留。候选启用失败会尝试停止候选并恢复部署记录，不自动重新连接；停止未完成时保留故障身份，按状态处理。检查当前状态后再手动连接。

本次验证包括原生界面交互、状态隔离测试、新配置的真实 sing-box 校验与隔离引擎切换测试。真实重启、登录任务、第二台服务器与第二台客户端仍需对应环境验收。预览版尚无正式服务、商业签名安装器与加密身份恢复包。
