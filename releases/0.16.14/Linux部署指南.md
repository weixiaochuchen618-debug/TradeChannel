> 0.16.11 的标准入口是「部署 → 添加线路」：填写地址和密码，点击「部署这台服务器」，核对首次身份后自动准备 UDP/TCP。密码可显示／隐藏，有效登录资料默认按任务加密保存，最长 24 小时。普通部署请使用 [新手指南](新手部署指南.md)。以下是早期独立控制台的分步维护参考，其按钮、逐步登录和不保存密码的说明不适用于当前自动向导。

# Linux 服务器部署与迁移

向导入口：TradeChannel → 部署 → 部署 Linux 服务器。在本地 Windows 电脑操作，服务器无需安装桌面或 Windows 版 TradeChannel。

本流程建立独立的新节点，保留本机当前线路。适配目标为专用 Ubuntu Server 24.04 / Debian 13 的 x86_64 VPS。程序部署、外网转发、重启恢复、实际交易验收分别记录，不能只看到「已应用」就停用旧服务器。

## 开始前准备

- 云控制台显示的服务器公网 IPv4、SSH 端口及用户名。通常 SSH 端口为 22，用户名 root；其他用户需要免密码 sudo。
- SSH 登录密码，或供应商提供的 SSH 私钥文件。密码/密钥口令只在独立登录窗口输入，不放进聊天、截图、迁移包或界面任务资料。
- 云控制台或供应商提供的 SSH 主机指纹。若控制台没有显示，可通过厂商网页控制台，在服务器执行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256` 查看，然后与登录窗口的指纹对照。
- 云安全组管理权限，以放行 WireGuard UDP 端口。保留厂商网页控制台，便于管理。

服务器需要能访问其官方软件源。Linux 使用发行版的 WireGuard 软件包，不使用 Windows 版 WireGuard EXE。裸系统缺少 `python3` 时，先在云控制台运行 `apt-get update` 和 `apt-get install -y python3`，再回向导重试。

## 1. 填写服务器资料

1. 填公网 IP、SSH 端口、用户名。
2. 给新节点起名称，例如「香港 Linux」；之后可在本机线路列表中区分旧节点。
3. WireGuard UDP 端口默认 51820。它与 SSH 的 TCP 22 是两种服务，两个端口都应保留。
4. 隧道网段默认 `10.78.0.0/24`；不能与本地局域网、当前隧道或服务器网段重叠。
5. 使用密码登录时，SSH 密钥文件留空。使用密钥登录时选择厂商提供的文件，这不是 WireGuard 的密钥。

点击「连接并检查」。此步不会安装通道或修改本机路由。

## 2. 登录并检查

会打开独立的 OpenSSH 登录窗口：

- 第一次连接会提示主机 SHA256 指纹。与云控制台核对一致后输入 `yes`。
- 提示 `password` 时输入 SSH 登录密码；提示密钥 `passphrase` 时输入密钥口令。输入期间不显示星号是正常现象。
- 指纹变更时不要关闭校验继续连接，应先核实服务器是否重装、IP 是否变化。
- 不要关闭正在处理的窗口。关闭后如果结果不明确，应先检查服务器状态，再决定重试或恢复。

工具检查系统、权限、网卡、路由、现有隧道和防火墙。已有 Docker、复杂防火墙或其他 WireGuard 服务时，不会清空规则强行部署。检查未通过的原因会显示在页面中。

首次版本每个远程步骤可能分别请求登录。使用已解锁的 SSH 密钥可以减少重复输入；工具不保存登录密码，也不修改服务器 SSH 认证方式。

## 3. 审阅计划与安全组

环境通过后点击「生成部署计划」。此步在本机生成设备身份，仅发送公开设备申请；客户端私钥留在本机。

核对计划里的服务器地址和节点名称。在云厂商控制台找到该服务器的安全组/防火墙：

| 协议 | 端口 | 用途 |
|---|---|---|
| TCP | 当前 SSH 端口，通常 22 | 保留管理访问 |
| UDP | 计划中的 WireGuard 端口，通常 51820 | 交易电脑连接新通道 |

TradeChannel 未接入云厂商 API，因此不会替你点击云安全组。根据厂商允许的范围限制来源；本机公网 IP 经常变化时，过窄的来源限制会导致换网后连接失败。

如果不知道 UDP 在哪里设置：用浏览器登录购买 VPS 的网站，进入「服务器／实例列表」，点开这台 VPS，寻找「安全组」「云防火墙」或「防火墙规则」。在绑定到这台 VPS 的规则中添加**入站／入方向**规则，协议选 **UDP**，目标端口填 **51820**（若计划改了端口，以计划为准），动作选「允许」，保存并确认规则已绑定到本机。这里的“本机”指这台 VPS，不是交易电脑。保持原有 TCP 22 管理规则。

来源填写交易电脑的公网 IP；固定来源可用 `公网IP/32`。公网 IP 经常变化且厂商要求填写时，可用 `0.0.0.0/0` 允许从任意 IPv4 发起 WireGuard 握手，实际隧道仍需设备密钥授权。若控制台明确显示没有启用云防火墙、所有入站均已允许，就不必再创建重复规则。找不到入口时，提供厂商名称或服务器详情页截图即可，不需要提供密码。不要在 Windows WireGuard 界面里找这项设置。

**已有新鲜的 WireGuard 握手及经新节点出网成功记录时，不应因为 HTTPS 慢就反复调整 UDP 放行。** 应继续核查带宽、丢包、实际转发及测试路径；能握手和能稳定交易是不同验收项。

完成云安全组后勾选确认，点击「应用到新服务器」。目标、影响和步骤会再次展示。

## 4. 自动安装与授权

工具自动安装所需组件，生成服务器身份，配置限定网段的 NAT、转发、防火墙及系统服务；不会重装服务器、改变服务器公网默认路由或安装图形桌面。

正常完成后显示「已应用 · 外网与重启恢复待验证」。重复执行同一计划不会重新生成身份或覆盖其他设备；检测到配置被手工修改时会停止，避免覆盖不明改动。

遇到失败请查看具体状态。只有属于本产品、且与事务记录一致的资源可以恢复；恢复失败会明确显示，不会宣称成功。通过软件源安装的依赖包通常会保留，不把它们计为已完全撤销。

如果首次部署已经创建全部资源，但因检查中断而留下未完成记录，可在对应失败任务中选择「核验并完成部署记录」。只有文件、身份、服务、路由及防火墙全部符合原计划时才会提交记录，不会重新安装或跳过差异。这项核验可处理已过期的原计划；「应用」仍禁止执行过期计划。「恢复未完成的部署」执行回退，请按实际需要选择。

## 5. 导入本机并迁移

1. 点击「生成本机配置并进入导入向导」。工具核对请求、响应和本机私钥，合成纯客户端配置。
2. 继续向导，确认 NinjaTrader 程序、本地 DNS 和要纳入的服务商，然后保存新节点。
3. 此时新节点只是已登记，没有接管正在使用的香港线路。
4. 安排维护窗口，先独立验证新节点的公网出口和交易服务；处理好账户状态，退出整个 NinjaTrader 后再切换。
5. 重新登录，检查实时行情、历史 K 线、TradingView 及跟随交易线路的 AI。切换服务器会改变这些流量的公网出口，需要重连。
6. 在新节点正式承载交易前，实际重启新服务器并确认恢复。观察一个计划交易时段，确认稳定后才退役旧服务器。

旧节点、旧设备身份和完整运行文件先保留。设置迁移包不包含私钥，不是可直接恢复连接的完整备份。若新节点影响 agent 网络，恢复应由本机独立任务执行，不能依赖在线聊天救场。

## 常见问题

| 现象 | 处理 |
|---|---|
| 没有弹出登录窗口 | 检查 Windows OpenSSH 是否安装、入口是否以管理员启动，再查看本机任务状态 |
| 一直提示登录失败 | 核对公网 IP、用户名、SSH 端口和密码/私钥，供应商有时禁用 root 密码登录 |
| sudo 需要密码 | 初版后台操作要求 root 或免密码 sudo；不要把 sudo 密码写进命令，按厂商提供的管理方式准备权限 |
| 安装成功但隧道不通 | 检查云安全组的 UDP、服务器本地防火墙、实际握手和外网转发，ping 成功不能代替这些检查 |
| 关闭界面后找不到任务 | 回到 Linux 向导，点击「查看近期任务」，继续已有计划或检查结果 |
| 计划过期或服务器状态变化 | 重新检查并生成新计划，不直接套用旧计划 |
| SSH 中断，结果不确定 | 先检查服务器状态。若有未完成事务，按向导恢复后再继续，不重复创建新的节点 |

原理依据：[WireGuard 官方快速开始](https://www.wireguard.com/quickstart/)、[wg-quick 官方手册](https://manpages.debian.org/trixie/wireguard-tools/wg-quick.8.en.html)。本产品的自动化验收范围以随项目保存的实际记录为准。
