打开程序保持当前连接。部署中心统一添加线路、继续准备和操作历史；连接成功与交易、AI 工具的实际使用分别检查。

添加线路中断与重装新增电脑日常使用整理记录

首次配置或新增服务器

1 · 添加线路

提供接入资料。软件识别电脑和服务器状态，无需自己判断是哪一种部署场景。

2 · 自动准备

核对目标与范围后，串联服务器 UDP/TCP、本机授权、配置保存和独立检查。

3 · 已准备

完整结果自动保存。明确启用前，当前连接保持；也可以稍后使用。

  1. 打开「部署 → 添加线路」，粘贴服务器资料。
  2. 密码登录填写服务器账户密码；SSH 私钥登录选择本机密钥文件，私钥口令只用于解密该文件。用户名和端口可在高级区修改。
  3. 首次或变化后的主机指纹与云控制台等可信来源核对，再确认本次准备的目标与影响范围。
  4. 软件自动准备服务器和本机的 UDP/TCP 配置。需要云账户操作时，按本次端口清单放行，再回当前页继续检查。
  5. 完整准备自动保存。TCP 未完成、连接检查失败或原结果未知时，按照同页提示继续，不把已保存误当成检查通过。
  6. 点击「启用这条线路」，核对交易、日常、AI 的流向及中断影响。退出 NinjaTrader 后明确确认，才接管本机网络。
已经安装过组件的电脑会复用组件和有效偏好。新增服务器仍要生成本机对应的授权和连接配置；服务器服务安装完成不等于整条线路已验收。

登录失败、部署中断与服务器重装

从部署中心的「继续部署／继续准备」回原步骤。认证失败在当前页补齐凭据；结果未知先核对原事务和原申请，避免重复授权。

软件分别核对 SSH 主机身份和实际隧道身份。同指纹也可能发生应用重置；只有 SSH 密钥更新时保留已经核验的原设备申请。新的应用环境使用新身份，旧记录归档。

为已有服务器新增一台电脑

  1. 管理电脑在「线路 → 服务器与设备」登录目标、生成邀请，可信交给新电脑。
  2. 新电脑在「添加线路」打开或粘贴邀请，核对来源后生成独立申请。
  3. 管理电脑打开申请、核对设备并批准，再把加密返回交给原申请电脑。
  4. 新电脑打开返回资料，继续本机配置与检查，最后明确启用。

当前电脑只显示当前需要的步骤。交接使用完整资料或文件；新电脑无需服务器密码。返回丢失使用同一份原申请，不复制旧电脑私钥共同连接。

日常连接与切换协议

线路卡显示已保存的默认 UDP/TCP；另一种已准备的连接方式可由用户主动选择。备齐后日常使用无需再次登录服务器补部署。短期推荐过期不删除配置，连接仍校验身份、配置、恢复状态和实际出口。

正在使用的设备身份不会并行探测。没有默认、已知失败或有未决事务时，按具体提示处理。通用探测通过后，仍需核对 NinjaTrader 登录、实时行情和历史数据；它不能解除 AI 平台地域限制。

概览中的流量走向使用有效服务商和线路。连接或切换会说明影响；关闭方式在设置中选择，收起到托盘和退出管理界面都保持后台连接。重启电脑后需手动连接。

管理历史记录

「管理已识别服务器」用于维护有明确管理地址及应用身份的服务器，入口数量与列表一致。未完成准备从部署中心继续；真实邀请接入从对应线路查看权限。缺地址的空白登记不再显示为邀请。

「部署 → 操作历史」支持单条、多选和全选当前结果后删除；部署中心和服务器管理也有清理入口。确认页列出关联服务器新旧身份、操作、线路配置、文件及保留项。确认后永久清理这些本机资料，不能恢复显示。当前线路、执行中或结果尚未核对的操作、未释放的检测资源需先处理。

共享资料、外部私钥和源配置会保留并列明。意外中断后从部署中心完成本机恢复，再继续添加。清理不卸载远端服务器。“显示旧版隐藏记录”只恢复升级前隐藏的记录；尚未执行部署的草稿可“放弃本次添加”，再恢复填写。

现有配置与高级维护

现有 .conf 或 WireGuard .zip 配置从部署中心的「打开连接资料…」导入；购买准备、迁移到新电脑、Windows Server 部署和管理恢复导入均在部署中心顶部。已部署服务器从「线路 → 服务器与设备」继续维护。高级操作见 Linux 部署指南。

设备撤权、本机线路移除、服务器卸载与云资源释放是不同操作。移除本机记录不停止云计费。
